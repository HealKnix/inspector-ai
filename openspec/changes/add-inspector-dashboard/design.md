## Context

`DashboardPage` компонует статические ChatPanel/InsightsWorkspace; SystemStatusPopover рисует успешную доступность без запроса. Реальные `ObjectsPage`, `VerificationObjectIndex`, ObjectAccess и протокол уже существуют. См. proposal.md; новый список объектов или независимый store результатов не нужен.

## Goals / Non-Goals

Цель — рабочая точка входа и корректная сводка в пределах доступа. Новый чат-агент, прогнозы, свободно придуманные KPI, управление моделями и собственный мониторинг вне scope.

## Decisions

1. Использовать существующие query hooks и маршруты; недостающие агрегаты получает read-only API с server-side ObjectAccess. Альтернатива собирать счётчики по первой странице объектов отвергнута: пагинация скрывает результаты.
2. Числа привязаны к одному текущему run/protocol и времени чтения; исторические версии явно отделены. Строки матрицы, coverage, unresolved candidates, confirmed, missing/clarification/suspicion не складываются в одно «нарушения». Неизвестные показатели остаются неизвестными.
3. Фильтры раздел/статус/дата хранятся в URL; сортировка и пагинация стабильны. Отдельно подписываются итоги фильтра и общие итоги доступного набора. Обновление данных не переносит пользователя на другой объект.
4. H ограничен назначенными объектами, настоящими статусами и переходом в ядро. F добавляет полный dashboard, события истории, синхронизацию и гипотезы после готовности их API. Нет циклической зависимости: другие модули публикуют данные независимо от dashboard.
5. UI health показывает только проверенный объём здоровья и время проверки. Нет мониторинга — явно нет данных; uptime 90 дней берётся только из реального monitoring API. Ошибку нельзя преобразовать в нулевую очередь или «всё завершено».

## Risks / Trade-offs

- N+1 запросы по объектам → ограниченный endpoint агрегирования после согласования DTO, измерение p95 с C24.
- Смена роли/отзыв назначения → очистка соответствующих query caches и отказ прямой ссылки на сервере.
- Переходный период со static demo → демонстрационный маршрут маркируется, не выбран как основной и не участвует в счётчиках.

## Migration Plan

Подключить новый read-only экран за существующим auth, сохранить рабочие deep links; переход к exports/history делать только после появления контрактов. Откат возвращает доступный реестр объектов, а не макет с фиктивной статистикой; данные БД не изменяются.
