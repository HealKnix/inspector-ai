# Рабочая сводка инспектора

## Why

Главная страница содержит статический пример найма Workday и не отражает реальные проверки. Инспектору нужен переход от назначенных объектов и состояния проверки к документам, доказательствам и сохранённому протоколу, без ложных счётчиков готовности.

## What Changes

- Фаза H: заменить основной путь статического макета реальной очередью назначенных объектов и проверок, связать с существующими upload/verification маршрутами, показать источник и время актуальности данных.
- Разделять количество строк матрицы, реально сопоставленных параметров, кандидатов, подтверждённых нарушений и недостаточных данных; фильтры не меняют смысл общих счётчиков.
- Фаза F: сводка по разделам, статусам и датам, история/комплектность/гипотезы/синхронизация, доступные действия и переход к экспорту выбранной версии; объём показателей подтверждается §7 ТЗ, без придумывания аналитики.
- Убрать статическое заявление «система работает штатно»: показывать проверенный health/время либо явную недоступность сведений, не изображая измеренный SLA.

## Capabilities

### New Capabilities

- `inspector-dashboard`: доступная по назначению сводка реальных проверок и навигация по текущим результатам.

### Modified Capabilities

Нет. Загрузка, протокол, история и мониторинг остаются отдельными capabilities.

## Impact

C17. Зависимости: существующий ObjectAccess, `add-inspector-verification`, `add-protocol-exports`, `add-audit-history`; будущие SUSPICION и внешняя синхронизация поставляют данные без изменения их семантики. Затрагиваются frontend dashboard/sidebar и read-only API агрегатов. [Итоговое ТЗ](../../../docs/requirements/SOURCES.md), §7/§9; поздний Q&A допускает общий интерфейс и не делает Medium-дашборд блокером сдачи. Минимальный рабочий путь H нужен для проверки ядра; полный F не считается готовым по одному экрану.
