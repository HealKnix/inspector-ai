# C14. Свободный поиск гипотез

Владелец: P3 алгоритмы, P1 данные/очередь, P2 интерфейс, P4 предметная оценка. Этапы 2–3 используют контракт этапа 1; UI можно готовить по нему параллельно. Приёмка — по [спецификации](specs/cross-stage-hypotheses/spec.md), без отметок реализации на основании плана.

## 1. Контракт и контрольные примеры

- [ ] 1.1 Описать версионированный результат каждого из четырёх методов: объект, scope, редакции, метод, объяснение, evidence и версии. Проверка: валидные/неполные/чужие источники проходят отдельные контрактные сценарии, нет автоматического CONFIRMED_VIOLATION.
- [ ] 1.2 Составить разрешённый validation-набор положительных гипотез, опровергающих примеров и конфликтов редакций; зафиксировать object split и хеши. Проверка: независимый от hidden манифест и экспертные ожидания доступны для повторения.
- [ ] 1.3 Согласовать вход HYP→VER, полномочия перевода и идентичность/версию атомарного правила вне Матрицы с VER/EXPORT/GOLD. Проверка: контракт сохраняет гипотезу, scope и назначение на объект, не требует фиктивного P133 или случайного Pxxx и описывает совместимость исторических findings.

## 2. Хранение и обработка

- [ ] 2.1 Добавить аддитивное хранение гипотез, вне-матричных правил и их доказательств с ограничением по object/snapshot/version. Проверка: миграция на пустой и заполненной тестовой БД сохраняет старые протоколы и допускает доказанный кандидат без MatrixRow.
- [ ] 2.2 Подключить долговечное задание к существующей очереди с ограничением попыток и fencing. Проверка: повтор сообщения, рестарт и поздний результат не дублируют карточки и не меняют новый Run.
- [ ] 2.3 Реализовать дедупликацию внутри сопоставимых редакций и областей. Проверка: повтор одной гипотезы объединяется, одинаковый текст разных объектов/помещений остаётся раздельным.

## 3. Четыре метода поиска

- [ ] 3.1 Реализовать логический метод на утверждённых условных правилах и типизированных фактах. Проверка: срабатывание, опровержение и неизвестная предпосылка имеют разные объяснения, пример ТЗ не превращён в универсальную норму.
- [ ] 3.2 Провести ограниченный локальный validation-эксперимент семантического метода и закрепить выбранные веса/конфигурацию/лицензию. Проверка: сохранены baseline, время, память, ошибки и проверка цитат без внешних вызовов.
- [ ] 3.3 Подключить выбранный семантический метод с проверкой file/page/quote/locator. Проверка: выдуманная страница, инструкция внутри документа и неверная редакция не дают доказанного кандидата.
- [ ] 3.4 Реализовать нормативный метод через утверждённые применимые версии нормативов MAT. Проверка: действующая, отменённая и неприменимая норма дают корректно различённые результаты с источником.
- [ ] 3.5 Подготовить baseline ML-паттернов на разрешённых исторических объектах и реализовать его локальное исполнение. Проверка: object split, параметры и метрики сохранены; отсутствие пригодной истории оставляет этот пункт открытым.

## 4. Рабочий путь инспектора

- [ ] 4.1 Добавить отдельную очередь SUSPICION с фильтрами по методу и переходом к исходным фрагментам. Проверка: гипотезы не увеличивают число нарушений и не смешиваются с недостающими документами.
- [ ] 4.2 Реализовать перевод в атомарный CANDIDATE только при полном доказательстве и разрешённой версии. Проверка: вне-матричный кандидат проходит реальное решение VER с собственной идентичностью; неполные evidence, чужой объект, stale версия и финализированный протокол отклоняются с причиной.
- [ ] 4.3 Передавать гипотезы в отдельную часть протокола и исключать сырые гипотезы из GOLD/внешнего обмена. Проверка: потребители сохраняют идентичность вне-матричного правила после экспертного решения, раздельный учёт и неизменное число 132 матричных параметров.

## 5. Приёмка и выпуск

- [ ] 5.1 Выполнить реальный офлайн-прогон четырёх методов на разрешённой выборке с экспертным разбором. Проверка: есть метрики по методам, coverage, ошибки и доказательства; отсутствие метода не скрыто общим результатом.
- [ ] 5.2 Проверить миграции, права, повторные задания, UI и сохранность истории при выключении worker. Проверка: применимые тесты/typecheck/build проходят и описаны в evidence.md.
- [ ] 5.3 Передать OFF модели/конфигурации, ACC — неизменяемый манифест и результаты. Проверка: другой оператор воспроизводит тот же сценарий по инструкции без скрытых локальных настроек.
