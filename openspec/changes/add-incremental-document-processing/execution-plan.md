# Поэтапная реализация INC

План от 26.09.2026. Существующие первый этап ID и PAR дают новые Run, снимки, повторное использование OCR и защиту истории. Исходные задачи INC остаются открытыми до полного охвата; повторно создавать уже работающую основу не требуется.

| Этап                                | Задачи tasks.md  | Порядок и выход                                                                                                               | Критерий готовности                                                                                          |
| ----------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 1. Контракты и LC-08                | 1.1–1.4          | Сверить действующие Process/Run/PAR/ID/протокол → закрепить права/переходы оставшихся событий → определить владельцев портов  | Подтверждённые сценарии не отменены, нет выдуманного enum; спорные переходы имеют явного владельца           |
| 2. Снимки и защищённые операции     | 2.1–2.2, 2.5–2.7 | Расширить текущую пару hash → проверить канонизацию/версионность → единая транзакционная граница загрузки/уточнений/протокола | Неизменяемая история, атомарные разрешения и отсутствие READY без настоящего протокола                       |
| 3. Граф и теневой план              | 2.3, 5.1         | Записывать найденные и ожидаемые зависимости → транзитивное замыкание → объяснение инвалидаций → сверка с полным прогоном     | Все пять классов изменений дают эквивалентный результат; изменившиеся старые группы не пропущены             |
| 4. Выборочное исполнение            | 2.4, 5.2         | Versioned план → reuse только неизменных оснований → selective dispatch → безопасный fallback legacy → rollback               | Изменённые доказательства снимают право переноса решения; повтор без дублей, старый протокол не меняется     |
| 5. Восстановление и внешний порт    | 2.8–2.9, 3.1     | Путь исправления по LC-08 → API/UI актуальности и разрешённых действий → событие внешнего поступления после FINALIZED         | UI показывает доступное действие; финализированный процесс не меняется и автоматически не запускается заново |
| 6. Конкуренция и производительность | 4.1–4.3, 5.3     | Реальная PG/Rabbit конкуренция → late worker → сравнение времени/объёма с полным запуском → evidence                          | Снимки согласованы с протоколом, выигрыш измерен, реальные C10/C12/C20 испытания выделены отдельно           |

P1 ведёт граф/транзакции, P2 — процесс/UI, P3/P4 помогают с эталонными зависимостями и версиями правил. Этап 3 можно готовить на согласованных входах параллельно с контрактами UI; selective dispatch включается после теневой проверки. Этап 5 зависит от оставшихся решений LC-08, но граф не должен ждать неотносящихся к нему внешних договорённостей.

До реальной интеграции COM/EXT/GEO проверка порта остаётся компонентной. Внешний адаптер и доставка уведомлений принадлежат C20/C23; INC регистрирует событие и сохраняет неизменность. Общие тайминги и конкурентный сценарий с настоящей финализацией принимаются add-release-acceptance. См. [design.md](design.md) и [спецификацию](specs/document-processing-lifecycle/spec.md).
