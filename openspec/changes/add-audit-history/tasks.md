# C21 — предметная история

H — прослеживаемость ядра; F — полный журнал и совместная эксплуатационная
проверка. AuditEvent и finding_decisions расширяются, повторно не создаются.
Retention/централизованная доставка принадлежат C23.

## 1. H — полнота и структура событий

- [x] 1.1 Составить coverage-map существующих событий upload/retry/clarification/decision/generate/finalize/cancel и новых evidence/split/export/exchange; проверка: у каждой операции перечислены автор, время, причина, версии и непокрытые поля.
- [x] 1.2 Зафиксировать безопасный envelope и read DTO, включая IP/user-agent по ТЗ и явную неизвестность старых значений; проверка: schema fixtures не содержат секретов/полного текста, неизвестные поля не выдумываются.
- [ ] 1.3 Дополнить недостающие записи в транзакциях владельцев операций; проверка: отказ аудита откатывает обязательное изменение, повтор не создаёт второй предметный эффект.
- [ ] 1.4 Добавить индексы/аддитивную проекцию чтения без перезаписи истории; проверка: миграция на копии старой БД сохраняет все решения/версии и их hashes.

## 2. H — история карточки

- [x] 2.1 Реализовать защищённое чтение истории объекта/протокола с устойчивым курсором; проверка: новые события между страницами не вызывают потери/дубли, чужой объект возвращает отказ.
- [ ] 2.2 Подключить историю находки/версии в рабочий UI с переходами к frozen evidence; проверка: после дозагрузки авторство/основание и локаторы прежнего решения сохраняются.
- [ ] 2.3 Показать отмену/перенос/split как связанные новые действия; проверка: UI не выдаёт копию старого решения за новое экспертное решение и не скрывает исходного родителя.

## 3. F — журнал и политика доступа

- [ ] 3.1 Зафиксировать полномочия на межобъектный журнал/выгрузку отдельно от обычного ObjectAccess; проверка: решение владельца и тестовая матрица доступа приложены, новые права не включены до решения.
- [ ] 3.2 Добавить подтверждённые фильтры по объекту/действию/времени/пользователю и UI журнала; проверка: пагинация и фильтрация сохраняют контекст версии и не раскрывают чужие реквизиты.
- [ ] 3.3 Подключить события новых модулей по мере их реализации; проверка: coverage-map связывает каждую запись с реальной операцией и тестом, отсутствующий producer остаётся открытым.
- [ ] 3.4 Согласовать ProtocolDiff с INC и реализовать API/UI типизированного сравнения двух сохранённых версий; проверка: добавление/замена источника, смена правила, перенос решения и необходимость перепроверки различимы, несопоставимость явна, смена renderer не создаёт предметный diff и чужая версия недоступна.
- [ ] 3.5 Реализовать AuditExport по полномочиям 3.1 и согласованному формату; проверка: файл содержит разрешённые event_id, фильтры, границы/момент среза, количество строк, версию схемы и хеш, исключает секреты, сам экспорт аудируется, отзыв доступа блокирует выдачу.
- [ ] 3.6 Согласовать с HARD/ИБ и реализовать запрет UPDATE/DELETE аудита прикладной ролью и независимый IntegrityCheckpoint; проверка: тесты подмены/удаления/перестановки обнаруживают нарушение, обычная роль не меняет контрольную точку, инцидент передаётся OBS, молчаливое перехеширование не скрывает следы. Механизм, периодичность и защищённое место контрольных точек утверждаются до включения.
- [ ] 3.7 Согласовать отдельную RetentionPolicy протоколов/решений/evidence и реализовать предметный архив с HARD/OBS; проверка: утверждены сроки/права/ограничения удаления, архивный период не показан пустым журналом, восстановление на изолированном стенде возвращает цепочку с исходными ID/хешами/авторством/frozen evidence и контрольной точкой, ротация технических логов её не удаляет. Физический backup/restore остаётся у HARD.

## 4. Совместная приёмка

- [ ] 4.1 Проверить цепочку приём→уточнение→доказательство→решение→финализация→отмена→обмен на изолированном контуре; проверка: по аудиту восстанавливаются версии/авторы/причины без обращения к полному содержимому логов.
- [ ] 4.2 С владельцем C23 проверить retention 90 дней/1 год и отделение предметной истории от ротации логов; проверка: отчёт ротации/восстановления не теряет историю протоколов и отмечает неподтверждённые эксплуатационные меры.
- [ ] 4.3 Выполнить проверки доступа/редакции секретов/миграции и релевантные typecheck/test/build; проверка: evidence.md фиксирует команды и оставшиеся пробелы покрытия.
