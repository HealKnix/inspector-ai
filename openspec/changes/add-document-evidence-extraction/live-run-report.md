# Отчёт о живом прогоне — 7 документов через весь конвейер

Дата: 2026-09-19/20. Окружение: `docker compose` (postgres, rabbitmq, redis,
clamav, parser PP-DocLayout/PP-OCRv5, backend, parsing/classification/extraction
workers). LLM: OpenRouter `qwen/qwen3.8-27b` (`CLASSIFICATION_LLM_ENABLED=true`).
Объект: «Октябрьская 103 — тестовая загрузка (devin)»
(`48bb0eb4-ce6f-4a75-9077-1ccaa3613b88`), загрузчик `devin.test` (INSPECTOR).

## Этап 2. Классификация (стадия PD/RD/ID)

Двухступенчатая схема: сначала локальные правила (собственный титул,
основная надпись/штамп), при отсутствии надёжных признаков — LLM.

| Документ    | Стадия   | Метод   | document_kind   | Reasons                                               |
| ----------- | -------- | ------- | --------------- | ----------------------------------------------------- |
| МОДИ        | **PD**   | rules   | —               | `own_document_title`, `own_stage_cell`                |
| ПЗ-фрагмент | **PD**   | **llm** | «Сводная часть» | `llm_requires_review`, `bounded_context`              |
| КЖ1.1       | **RD**   | rules   | —               | `own_document_title`, `own_stage_cell`                |
| КЖ0.6       | **RD**   | rules   | —               | `own_stage_cell`                                      |
| Исп.схема   | **null** | **llm** | —               | `llm_insufficient_evidence`                           |
| Сертификат  | **null** | **llm** | —               | `llm_insufficient_evidence`                           |
| ПОС2        | **null** | rules   | —               | `conflicting_own_evidence`, `possible_mixed_document` |

Особый случай ПОС2 (98 стр.): правила нашли обе семьи признаков — PD
(`«ПРОЕКТНАЯ ДОКУМЕНТАЦИЯ»`, штамп `«П»`/`«Стадия»`) и ID
(`«освидетельствования скрытых работ.»` — в ПОС вложены бланки АОСР
как приложения). Движок вернул `stage:null` с кандидатами и обеими
группами доказательств — конфликт оставлен инспектору, а не разрешён
угаданным классом. По контракту конфликт не эскалируется в LLM.

### Что видели правила (method=rules)

- МОДИ → PD: цитаты `«ПРОЕКТНАЯ ДОКУМЕНТАЦИЯ»` (титул), `«П»` (ячейка
  «Стадия» штампа), `«Стадия»`.
- КЖ1.1 → RD: `«РАБОЧАЯ ДОКУМЕНТАЦИЯ»`, `«Р»`, `«Стадия»`.
- КЖ0.6 → RD: `«Р»` + `«Стадия»` (штамп основной надписи).

Все rules-исходы помечены `partial_parse_requires_review` — признак того,
что артефакт LOW_QUALITY и результат требует глаз инспектора.

### Что ушло в LLM и что вернулось

Вход в модель — **не документ целиком**: `buildClassificationContext`
сэмплирует ≤48 фрагментов / ≤18 000 символов, приоритет — блоки с
якорями `документаци|стадия|освидетельствован|исполнительн|аоср` и
верх страниц, round-robin по страницам. Каждый фрагмент —
`{page_number, block_id, text, bbox, structural_path}`. Имена файлов,
подписи и полный текст за границу провайдера не уходят.

| Документ    | Фрагментов | Стр. в сэмпле | Байт входа | Ответ LLM                                   |
| ----------- | ---------- | ------------- | ---------- | ------------------------------------------- |
| ПЗ-фрагмент | 48         | 17            | ~7.5 КБ    | `stage:PD, kind:"Сводная часть"` + 2 цитаты |
| Исп.схема   | 3          | 1             | ~2.1 КБ    | `stage:null`                                |
| Сертификат  | 3          | 1             | ~0.8 КБ    | `stage:null`                                |

ПЗ: модель процитировала `«Разработка проектной документации для объекта:
«Многоквартирный жилой дом с…»` (p15-b18) и `«ф) заверение проектной
организации о том, что проектная документация разработана»` (p14-b47) —
каждая цитата проверена на вхождение в реальный текст блока
(`classification_llm_citation_mismatch` отверг бы выдумку).

Исп.схема: в сэмпл ушли 3 OCR-фрагмента — растровый лист, повёрнутый
текст (`"птоdо оd a вни ndo o…"`). LLM честно вернула
`insufficient_evidence` вместо угадывания — ровно то поведение, которое
требует промпт («исп.схема может использовать основу рабочего чертежа» —
не выводить стадию из контекста).

Сертификат: LLM не стала насильно относить сертификат материала к стадии —
`stage:null`, пустые evidence. Промпт это прямо предписывает.

Время LLM-ответа: 12–20 с (reasoning effort=low). Результат метода `llm`
всегда `needs_review` — автоответ не считается финальным.

## Этап 3. Извлечение по матрице

Approved-правила на момент прогона (4 шт. из 132 строк каталога):

- **P002** «Общая площадь здания» (м²): cascade — table_lookup по сигнатуре
  ТЭП → regex-фолбэк `м2\s*[:\-]?\s*(\d[\d\s]*,\d{2})` у якоря
  «общая площадь здания», окно 3 блока.
- **P004** «Строительный объем (Общий)» (м³): regex
  `строительный объем\s*,?\s*в том числе:?\s*м?3?\s*([0-9][0-9\s]*[.,][0-9]+)`,
  окно 12.
- **P007** «Этажность (надземная)» (ед.): cascade — table_lookup → regex у
  якорей «этажность/этажей/количество этажей».
- **P015** «Категория надежности электроснабжения»: enum-план.

Как алгоритм «смотрит в документ»: `POST /admin/matrix/search` по терминам
«общая площадь», «строительный объем», «количество этажей» вернул окна —
например, p7-b21..b25 (заголовок ТЭП), p7-b60..b66
(`Строительный объем, в том числе:` / `м3` / `73 080,00`),
p8-b15 (`Общая площадь` → `м2` → `16 605,70`). Поиск идёт по
нормализованным блокам включая skipped-регионы (фикс include_in_main).

### Итоги извлечения (7 документов × 4 параметра = 28 исходов)

| Документ         | P002             | P004             | P007        | P015        |
| ---------------- | ---------------- | ---------------- | ----------- | ----------- |
| ПЗ-фрагмент (PD) | **16 605,70 m2** | **73 080,00 m3** | **17**      | no_evidence |
| ПОС2 (конфликт)  | no_evidence      | no_evidence      | no_evidence | no_evidence |
| МОДИ (PD)        | no_evidence      | no_evidence      | no_evidence | no_evidence |
| КЖ1.1 (RD)       | no_evidence      | no_evidence      | no_evidence | no_evidence |
| КЖ0.6 (RD)       | no_evidence      | no_evidence      | no_evidence | no_evidence |
| Исп.схема (ID?)  | no_evidence      | no_evidence      | no_evidence | no_evidence |
| Сертификат       | no_evidence      | no_evidence      | no_evidence | no_evidence |

Все `no_evidence` вне ПЗ — корректные: ТЭП-показатели живут в ПЗ,
а не в КЖ-листах, исполнительных схемах и сертификатах материалов.
Движок ничего не выдумал.

Извлечённые значения с локаторами (`evidence_fragments`):

- P002 `16 605,70` m2 — стр. 8, блок `p8-b15`, quote `«16 605,70»`,
  bbox `[0.175, 0.059, 0.498, 0.075]`.
- P004 `73 080,00` m3 — стр. 7, блок `p7-b63`, quote `«73 080,00»`.
- P007 `17` — стр. 7, блок `p7-b75` («Количество этажей» →
  «эт. 17, 5 + подземный этаж»; для «надземной» этажности 17 —
  семантически верно, хотя сырое значение сложнее).

`evidence_groups` по объекту собраны: члены с role `unknown` — т.к.
извлечение прошло до LLM-классификации ПЗ (stage:null на тот момент);
переизвлечение произойдёт при смене ruleset-fingerprint.

## Этап 4. LLM-драфт правила (админка)

`POST /admin/matrix/rows/P004/draft-llm` (на живом артефакте ПЗ):

- Модель за ~3.4 с вернула regex-план: anchors `[«строительный объем»,
«Таблица 1», «ТЭП»]`, `window_blocks:12`, `unit:["м³"]` — все якоря
  подтверждены по реальным блокам (`missing_anchors:[]`), создан draft v1.
- Dry-run v1 → честный `ambiguous` (паттерн `[^0-9]*` захватывал «3» из
  «м3» и соседние значения) — движок не выбрал произвольное.
- Ручной draft v2 с уточнённым паттерном → dry-run `extracted`
  `73 080,00 m3` → approve → воркер переизвлёк автоматически.
- Draft v1 остался `draft` навсегда — неутверждённое не исполняется.

## Дефекты, найденные в этом прогоне

1. `classification-llm`: `max_tokens=1600` без reasoning-ограничения —
   qwen3 обрезалась `finish_reason=length` → `invalid_result`
   (ПЗ-фрагмент 2 раза, Исп.схема 1 раз). Фикс: `max_tokens:8000` +
   `reasoning.effort:"low"` — после пересборки **обоих** образов
   (classification-worker имеет собственный image!) повторные retry
   succeeded: ПЗ→PD за 13 с, Исп.схема→null за 20 с.
2. Nginx держит upstream `backend` по IP со старта: force-recreate
   backend → 502 до рестарта frontend. Стоит завести `resolver` в
   nginx.conf (не исправлено — отдельная правка).
3. АОСР-файлы (Adobe Scan) отклонены `unsafe_format` — воспроизводимо;
   формат реально нестандартен, не баг конвейера.
4. `scanner_limit` ClamAV на 9.3 МБ — лимит ресурсов антивируса;
   документ можно загрузить повторно позже.

## Что осталось непроверенным

- UI-панели в браузере.
- Полный хит-рейт по 132 параметрам (в срезе 4 правила).
- `stage` в свежих extractions ПЗ остался null — извлечение предшествовало
  LLM-классификации; члены evidence_groups имеют role=unknown до
  следующего цикла.
