# Извлечение фактов по правилам

Владелец: P3 извлечение + P4 правила. Нумерация локальная; [SRC-x.y] указывает задачу исходного объединённого change, а не её текущий статус. [Карта переноса](../../SPLIT_MAP.md), [общие обязательства](../../SHARED_BACKLOG.md), [контракты](../../CONTRACTS.md).

Все задачи открыты: перенос и готовность планирования не означают реализацию. Backend/frontend/ML выполняются в рамках одного функционального change; завершение определяется его спецификацией.

## 1. Контракты и предпосылки

- [ ] 1.1 Проверить зависимости ID и C05-C18; закрепить версии входных/выходных контрактов из CONTRACTS.md. Проверка: у каждой используемой сущности и миграции есть один владелец, отсутствующая зависимость явно отмечена.

## 2. Данные и миграции

- [ ] 2.1 [SRC-2.6] Добавить схемы Extraction/Evidence/EvidenceGroup и reader версионированных Params/RuleVersion из C05/C18. Проверка: миграция не дублирует таблицы правил или PackageRequirement; значения имеют единицы, область и locator.

## 3. Реализация capability

- [ ] 3.1 [SRC-2.7] Подключить capability document-evidence-extraction к общим проверкам доступа/аудиту C01 и безопасным событиям/метрикам C23. Проверка: изменение оставляет автора/версию/корреляцию, запрос чужого объекта отклонён, содержимое и секреты отсутствуют в логах; транспорт уведомлений не реализован повторно.
- [ ] 3.2 [SRC-6.6] Реализовать движок типизированных извлечений, regex и семантических якорей с совместимой Sentence-BERT-моделью; проверка: значения/единицы/области извлекаются по активной версии правила и сохраняют evidence.
- [ ] 3.3 [SRC-6.20] Реализовать выход извлечений/Evidence_Fragments/Checks для потребителя сравнения; проверка: схема валидируется, все версии и координаты присутствуют, сам парсинг не создаёт CANDIDATE/NEGATIVE_VERIFIED/CONFIRMED_VIOLATION.
- [ ] 3.4 Согласовать с GEO общий JSON-контракт Extraction и добавить адаптер геометрических результатов без повторной реализации CV. Проверка: обе схемы совместимы, неподтверждённая метаинформация не подставляется.

## 4. Интерфейс

- [ ] 4.1 Показать значение, единицу, область, версии и переход к доказательству через viewer PAR. Проверка: пользователь видит источник, но не получает finding от одного факта извлечения.

## 5. Проверки и доказательства готовности

- [ ] 5.1 [SRC-11.9] Проверить повтор вычисления, неподдержанный план и смену RuleVersion во время job. Проверка: выход сохраняет свои версии, не публикуется как новый и не даёт фиктивного отрицательного результата.
- [ ] 5.2 Проверить самостоятельный результат на реальных зависимостях: Движок исполняет утверждённые текстовые/табличные планы, отклоняет неподдержанный тип и возвращает проверяемые факты с версиями. Отдельный реестр C18 сохраняет обязательство всех 132 строк; отсутствие реального модуля сравнения не блокирует проверку самого извлечения. Проверка: evidence.md содержит команды, версии, результаты и ограничения; mocks не используются как доказательство закрытия реальной интеграции.
- [ ] 5.3 Выполнить применимые проверки существующего репозитория для изменённых частей (тесты, typecheck, build) и проверку OpenSpec. Проверка: результаты записаны в evidence.md, auth не сломан, отложенные обязательства C24 перечислены без отметки выполнения.
