# C19/C20 — контрактный и реальный обмен

H/C19 можно проверять без оператора; F/C20 требует его контракта и стенда.
Зависимости: ING/INC/VER/exports; outbox C01, уведомления C23, журнал C21.
Наличие mock не закрывает real transport, УКЭП или совместную приёмку.

## 1. H — сервисный контракт

- [ ] 1.1 Сопоставить действующие upload/monitoring/results с Pull §9.6 и закрепить OpenAPI/JSON Schema версии и ошибок; проверка: контрактные примеры сохраняют process_id и различают незавершённость/отказ/готовый результат.
- [ ] 1.2 Зафиксировать модель авторизации внешнего клиента и область объектов; проверка: утверждённая политика и негативная матрица, без неё не создаются неявные service-principal полномочия.
- [ ] 1.3 Реализовать недостающий адаптер через существующие ING/INC/VER; проверка: таймаут клиента после acceptance не отменяет job, повтор не создаёт файлы/запуски повторно.
- [ ] 1.4 Зафиксировать mapping finalization/process/sync и экспортного payload; проверка: только финализированная версия и confirmed-записи проходят, candidates/suspicion исключены из нарушений.

## 2. H/C19 — настоящий локальный mock

- [ ] 2.1 Реализовать локальный mock получателя с receipt и управляемыми 4xx/5xx/timeout; проверка: запросы реально приняты/сверены со схемой, UI явно показывает mock.
- [ ] 2.2 Добавить долговечный реестр отправки и outbox-публикацию закреплённого payload; проверка: сбой после commit и рестарт сохраняют отправку и не меняют локальный FINALIZED.
- [ ] 2.3 Реализовать до трёх повторов 1/5/15 минут после первой попытки; проверка: управляемые часы доказывают предел/задержки, permanent error не образует бесконечный цикл.
- [ ] 2.4 Реализовать идемпотентный receipt/reconciliation после неоднозначного timeout; проверка: повтор внешнего эффекта не создаётся, состояние доставки наблюдаемо.
- [ ] 2.5 Подключить UI отправки/состояния/ошибки к реальному локальному обмену; проверка: кнопка перестаёт быть сообщением без операции, кандидаты и чужая версия не отправляются.
- [ ] 2.6 Проверить автоматический вход документов до/после финализации через общий порт; проверка: до final действуют лимиты/антивирус, после final нет нового run и сохранено событие уведомления.
- [ ] 2.7 Подключить доставку уведомления к C23 и запись попыток к C21; проверка: отказ канала виден и не теряет факт новых документов или неподтверждённой передачи.
- [ ] 2.8 Выполнить offline E2E локального mock и релевантные typecheck/test/build; проверка: evidence.md фиксирует отсутствие внешней сети, сценарии повторов и границу mock.

## 3. F/C20 — реальный оператор

- [ ] 3.1 Получить и закрепить контракт оператора, endpoint, wire-schema, сертификаты/подпись и окно приёмки; проверка: версии документов и разрешения зафиксированы, отсутствие входов оставляет F открытым.
- [ ] 3.2 Реализовать transport HTTPS/client certificates и подпись по полученному контракту; проверка: отрицательные тесты сертификата/подписи и отсутствие ключей в frontend/логах проходят.
- [ ] 3.3 Подключить реальные receipt/status/idempotency и предусмотренный контрактом автоматический забор файлов; проверка: стенд оператора подтверждает повтор, отказ и запрет чужого объекта.
- [ ] 3.4 Выполнить совместную приёмку отправки финализированной версии, недоступности и новых документов после final; проверка: отчёт оператора и локальные hashes совпадают, исходники/решения сохранены.
- [ ] 3.5 Проверить откат transport без потери pending attempts и принятых файлов; проверка: повторное включение продолжает согласованный обмен без двойных результатов, F не закрывается mock-отчётом.
