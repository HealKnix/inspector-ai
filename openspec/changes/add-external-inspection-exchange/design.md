## Context

Есть API документов и verification, но нет адаптера РиН. `ProtocolDetailsPage` остаётся demo. §9.6 задаёт общий маршрут передачи `POST /api/v1/inspection/{process_id}`, Pull и политику ошибок; адрес оператора, wire-schema, credentials и область доступа должны быть получены, а не выдуманы. Поздний Q&A допускает локальный mock и реальную offline-проверку ядра.

## Goals / Non-Goals

H/C19 — работающий сервисный контракт и локальный тестовый получатель. F/C20 — аттестованный обмен с оператором. Политика предписаний и их изменение не выводятся из названий ISSUED/IN_PROGRESS/COMPLETED/CANCELLED/EXTENDED; их отображение/приём возможны только по подтверждённому внешнему контракту. Автоматические санкции не входят в change.

## Decisions

1. Внешний слой вызывает существующие ING/INC/VER, а не пишет File/Protocol напрямую. Контракт включает принятие с process_id, отдельный мониторинг и Pull результата конкретной версии; незавершённость/технический отказ не возвращают пустое «успешно». Закрытие клиентского соединения не отменяет серверную работу.
2. Локальная финализация и sync — разные сущности/состояния. Экспортный снимок версии закрепляется до отправки; подтверждённые записи и manifest не изменяются при повторе. Только CONFIRMED_VIOLATION из финализированного протокола отправляется как нарушение; кандидаты/гипотезы/missing не включаются в число нарушений.
3. Outbox и реестр попыток дают долговечность; идемпотентный ключ передачи определяется protocol/version/получатель с согласованным wire-контрактом. 5xx/timeout — исходная попытка плюс до трёх повторов 1/5/15 минут. 4xx не запускает бесконечные повторы; неоднозначный timeout разрешается idempotency/status API получателя. Финальный локальный статус не откатывается; PENDING_SYNC относится только к доставке.
4. H содержит локальный mock server с контрактными fixtures, приёмом payload, receipt и управляемыми ошибками. Mock подписи/сертификата явно помечен. F добавляет real transport с утверждёнными TLS/client certificate/подписью; private keys только server-side. Ни mock, ни пользовательская роль не дают внешнему клиенту неявных прав: до реализации service principal фиксируется отдельная политика, иначе разрешены только действующие полномочия сессии.
5. Внешняя дозагрузка до final проходит те же лимиты/антивирус/idempotency. После final сохраняется факт новых документов и уведомление через C23, без нового run; создание новой проверки — отдельное явное действие по согласованному контракту.

## Risks / Trade-offs

- Нет спецификации/стенда оператора → F остаётся зависимым этапом; H проверяется локально и не называется интеграцией с настоящим РиН.
- Повтор после сетевой неопределённости → контрактные тесты receipt/idempotency и ручная сверка только при отсутствии безопасного автоматического статуса.
- Сбой после commit до отправки → outbox восстанавливается без потери протокола.
- Совпадающие именования protocol/process/sync → явная таблица соответствия PDF и текущей модели до миграций, без переименования публичных полей молча.

## Migration Plan

Аддитивно добавить реестр синхронизации и API contract, затем H mock; F включать отдельной конфигурацией после совместного теста. Откат отключает отправку, сохраняет pending attempts и локальные финальные версии; не удаляет принятые внешние оригиналы. Сертификаты/операторский endpoint являются входной зависимостью F, не задачей угадать их.
