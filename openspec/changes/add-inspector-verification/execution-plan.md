# Поэтапное завершение VER

План от 26.09.2026 продолжает существующий срез. Девять отмеченных задач
1–4 сохраняются; восемнадцать новых задач 5–7 открыты. Наличие generate,
решений, переходов READY/VERIFYING/COMPLETED/FINALIZED, версий и ADMIN-cancel
установлено по исходникам; новые прогоны при создании плана не выполнялись.

| Этап / gate                         | Задачи       | Последовательность и результат                                                                  | Условие перехода                                                                                        |
| ----------------------------------- | ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| VER-B — актуальный baseline         | 5.1          | Код и тесты → карта старых/новых возможностей → перечень ограничений                            | Реальный workspace не назван mock, исторический отчёт не назван новой приёмкой                          |
| VER-H1 — источники и решение        | 5.2–5.4      | Контракт ID/PAR → три применимые стадии → реквизиты → комментарий confirm                       | Нет подмены источника; поля и локаторы из закреплённого снимка; пустой confirm отклонён UI/API          |
| VER-H2 — авторские evidence и split | 5.5–5.8      | Согласовать версионные DTO/полномочия → backend → формы → конфликты                             | Старые фрагменты/родитель сохранены; дети атомарны; чужой источник и устаревшая версия отвергнуты       |
| VER-H3 — история и реальный цикл    | 5.9, 7.1–7.2 | INC/PAR/ID/EXT/COM/comparison → протокол → решения → final → дозагрузка/конкурентность          | Реальный разрешённый комплект и hashes; изменённые evidence не наследуют решение; final защищён         |
| VER-F1 — отмена и продолжение       | 6.1–6.4      | Зафиксировать переход после cancel → ADMIN UI → решение о супервизоре → разрешённое продолжение | COMPLETED не обходится, администратор не получает инспекторские права; исходная история final сохранена |
| VER-F2 — юзабилити и выпуск         | 7.3–7.5      | Пять инспекторов → измерения → исправления → повтор → exports/history regression                | 132 параметра/14 нарушений, ≤30 минут, ≤3 кликов; отчёт и релевантные проверки, ограничения указаны     |

H — работоспособное ядро для сдачи без внешней сети, F — полный объём ТЗ.
Показать существующие состояния можно до новых возможностей; это не снимает
их требований. Полный change закрывается по H и F, а не по готовности Markdown.

P1 владеет API/транзакциями/совместимостью, P2 — workspace и формами, P4 —
реальными сценариями/юзабилити, P3 участвует в проверке доказательств. 5.2–5.4
можно вести параллельно согласованию 5.5; 6.2 зависит от 6.1 только в части
показа дальнейших действий, сама безопасная ADMIN-отмена уже имеет API.

Входные зависимости: `add-document-parsing` (страницы/локаторы),
`add-document-identification` (редакции/утверждение),
`add-document-evidence-extraction` и `add-evidence-comparison` (группы/вердикт),
`add-document-completeness` (gate), `add-incremental-document-processing`
(актуальность/fencing/продолжение). Выходы: `add-protocol-exports`,
`add-audit-history`, GOLD и SUSPICION через согласованный контракт;
они не являются предварительным условием уже работающих решений. Совместная
проверка 7.5 ждёт их реализацию. Общая offline/качество/нагрузка принимается
`add-release-acceptance` и не закрывается локальным UX-отчётом.

Решения, требующие входа владельца: переход reopen после COMPLETED без новой
дозагрузки, матрица новых авторских evidence-операций и супервизорское
полномочие. План не выдаёт эти решения за уже утверждённые; зависимая
реализация начинается только после фиксации контракта, независимые этапы идут
дальше. См. [design.md](design.md), [tasks.md](tasks.md) и
[спецификацию](specs/inspector-verification/spec.md).
