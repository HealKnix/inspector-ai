## Context

Мотивация — [proposal.md](proposal.md). Существуют `MatrixImport/MatrixRow/RuleVersion`, JSONL всех 132 строк, API черновиков/dry-run/approve/reject и обновление worker по fingerprint. `approve` проверяет форму JSON, но не наличие предметного regression-отчёта; batch-скрипт использовал `extracted > 0`. Seed восстанавливает только P002/P007/P015. По evidence 26.09 в БД исполнимы 12 правил, сравнение задано у 11, P019 извлёк номер пункта, а текущий комплект не дал ни одной подтверждённой пары.

## Goals / Non-Goals

**Goals:** использовать существующую модель версий для доказательного допуска правил, сделать набор воспроизводимым и установить проверяемый знаменатель 132. **Non-Goals:** переписывать EXT/CMP или добавлять допуски и нормы без источника. Состояния готовности паспорта и regression-отчёта — внутренняя метаинформация; публичные enum расширяются только после явной спецификации совместимости.

## Decisions

### Два независимых рубежа

Этап A «основания и допуск» поставляет схему паспорта правила, контракт операторов/регрессий и проверку approve. Он не требует готовности всех строк, GEO или EVENT. После A параллельно идут CMP, C07, GEO, C09 и предметные партии. Этап F «полный выпуск» принимает результаты этих работ, проверяет 132/132 и экспорт. Зависимость операторов от полного F отвергнута: она образовала бы цикл.

### Паспорт связан с исходной строкой и версией

Сохраняются исходные поля MatrixRow; дополнительная версия описывает проверяемую величину, применимость, требуемые стадии/область, извлечение, оператор, единицы, округление/допуск, нормативное основание и конкретные локаторы источника. Нормативная ссылка включает редакцию/дату применимости и происхождение; неизвестное значение остаётся отсутствующим и блокирует только зависимую ветвь. Дословный триггер не заменяется LLM-пересказом. Отдельная параллельная таблица «новых 132 правил» отвергнута.

### Допуск требует регрессий той же версии

Report связывает hash правила, оператор/движок, разрешённые fixture hashes, ожидаемые значения/единицы/локаторы, исходы и автора предметной проверки. Для применимых ветвей нужны положительный, отрицательный, граничный и неопределённый случай; неприменимость категории примера обосновывается. Отсутствие реального отрицательного эталона не заменяется автоматически результатом модели: синтетика помечается, корпусная точность остаётся непроверенной. Изменение плана или основания инвалидирует прежний report. UI и прямой API соблюдают один gate.

### Предметные партии соответствуют Матрице

Текущие 12: P001/P002/P003/P004/P007/P009/P015/P019/P022/P023/P056/P058. Остальные 120 — разность полного каталога и этого списка, а не произвольно выбранный демонстрационный набор. Нумерация и названия берутся из JSONL/XLSX; предварительные профили прежней карты не являются утверждённой семантикой.

### Неизменяемый выпуск и перенос

Manifest перечисляет ровно P001–P132, ссылки/hash утверждённых версий, основания, результаты регрессий и совместимые версии исполнителей. Публикация атомарно выбирает проверенный manifest; смена active release не переписывает старые Run/протоколы. Откат выбирает прежний совместимый выпуск для новых расчётов. Экспорт содержит правила и необходимые разрешённые справочники/схемы, но не секреты или документы пользователей. Импорт проверяет hashes, авторизацию, совместимость и неизменность существующих версий; повтор идемпотентен.

## Risks / Trade-offs

- [Опечатка/неоднозначность Матрицы] → предметный вопрос привязан к строке, публикация этой ветви закрыта до ответа; оператор и другие партии продолжаются.
- [Переобучение regex на одном PDF] → раздельные документы/объекты для разработки и проверки, явная синтетика, raw/normalized/locator assertions.
- [Локальные 12 правил потеряны при чистой установке] → ранний снимок существующих версий, финальный офлайн round-trip и сравнение manifest/result hashes.
- [Новый gate мешает чтению истории] → старые версии остаются читаемыми; отсутствие нового report не маркируется как уже пройденная регрессия.

## Migration Plan

Добавить аддитивные паспорт/report/release данные, прочитать существующие версии без их переутверждения. Исправления публиковать новыми RuleVersion. Включить обязательный gate для новых утверждений после проверки совместимости API/worker. До полного релиза допускаются явно частичные выпуски с точным покрытием; они не получают отметку 132/132. Проверить чистый импорт без сети, повторный импорт и откат выбора выпуска, сохранив прежние протоколы.
