# Поэтапная реализация GEO

План от 26.09.2026. Все задачи [tasks.md](tasks.md) открыты; наличие viewer и координат PAR не закрывает геометрию.

| Этап                       | Задачи        | Шаги и результат                                                                                              | Критерий перехода                                                                                        |
| -------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 1. Правила и эталоны       | 1.1, 5.1      | Получить утверждённые геометрические планы → закрепить GeometryResult с EXT → разметить расстояния/виды/опоры | Нет выдуманных допусков; эталоны имеют hash и отделены от hidden test                                    |
| 2. Калибровка и измеритель | 2.2, 5.2      | Выделить вид → найти опору → определить локальный масштаб → измерить заданную геометрию → оценить ошибку      | Известные расстояния воспроизводятся; конфликт/неизвестность не дают достоверного числа                  |
| 3. Хранение и очередь      | 2.1, 2.3, 5.3 | Node-валидация → versioned job/result → fencing/idempotency → адаптер EXT                                     | Версии/единицы/опоры/локаторы полны, повтор без дубля, старый результат неизменен                        |
| 4. Overlay                 | 3.1           | Показать измеряемую геометрию, опору, единицу и ограничение в viewer PAR                                      | CropBox/Rotate не смещают доказательство; разные масштабы видны отдельно                                 |
| 5. Измеренная приёмка      | 4.1–4.4       | PDF-бенчмарк → ошибки/таймаут/повтор → реальные PAR/EXT/COM → evidence и проверки                             | Отчёт содержит абсолютную/относительную ошибку, объём выборки, оборудование и время; DWG отдельно открыт |

P3 ведёт CV, P4 — эталон/правила, P1 — контракт/очередь, P2 — overlay. Контракт и эталон можно готовить параллельно; UI по согласованной схеме начинается до готовности CV. Приёмка измерений требует реального алгоритма, не fixture числа.

Зависимости: PAR для координат и изображений; ID для применимого листа/редакции при публикации; C05/C18 для допустимых измерений/единиц/допусков; EXT для передачи доказательств. GPU измеряется в целевой среде отдельно от CPU. Конфликт PDF/DWG и общая производительность принадлежат add-release-acceptance. См. [design.md](design.md), [спецификацию](specs/drawing-geometry-analysis/spec.md).
