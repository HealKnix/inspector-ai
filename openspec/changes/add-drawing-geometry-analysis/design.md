## Context

См. [proposal.md](proposal.md) для мотивации и [spec](specs/drawing-geometry-analysis/spec.md) для поведения. В существующем коде есть auth, роли, Prisma и контейнер RabbitMQ; это не доказательство готовности C01. Новые предметные сущности отсутствуют. Изменения сохраняют /api/auth/*, текущий React-клиент и Bun workspaces. Источники — [PDF и приложения](../../../docs/requirements/SOURCES.md).

До завершения: [PAR](../add-document-parsing/proposal.md); общие зависимости C05-C18 в [SHARED_BACKLOG.md](../../SHARED_BACKLOG.md). Интерфейсы можно разрабатывать по согласованным контрактам до готовности зависимостей, но интеграцию закрывают на реальных компонентах.

## Goals / Non-Goals

**Goals:** определить границы данных, взаимодействия и доказательства результата capability drawing-geometry-analysis. GEO владеет алгоритмом и версией GeometryResult; базовые локаторы предоставляет PAR, предметные реквизиты — ID. Вызов не требует действующего EXT: результат валидируется по согласованной общей схеме, адаптер включается при совместной сборке.

**Non-Goals:** DWG-upload не добавляется; конфликт строки §11 №8 остаётся открытым в C24. Межстадийное предметное сравнение геометрии — отдельный потребитель, не часть этого change.

## Decisions

[Общий контракт](../../CONTRACTS.md) фиксирует владельцев, поля, версии и порядок интеграции. Технические решения ниже — проект реализации; подтверждённые роли и бизнес-статусы берутся из PDF.

### D1

Вход — ParseArtifact и область/правило измерения. Масштаб выводится из размерной линейки именно этой области; соседний вид или другой лист не предоставляет масштаб автоматически.

Основание и рассмотренная альтернатива: Глобальный масштаб листа неверен для нескольких видов; локальная опора позволяет проверить конкретное измерение.

### D2

Результат включает величину, единицу, геометрию объекта и опоры, калибровку, версии и происхождение. При неизвестной опоре возвращается объяснимое отсутствие измерения, не приблизительное достоверное число.

Основание и рассмотренная альтернатива: Число без калибровки выглядит достоверным при отсутствии доказательства. Явный отказ сохраняет качество последующего сравнения.

### D3

Измерения сохраняются как отдельный вид Extraction, совместимый с EXT. Преобразования CropBox/Rotate повторно не реализуются, используется контракт PAR.

Основание и рассмотренная альтернатива: Собственные преобразования создадут расхождение overlay с PAR. Совместимый контракт позволяет разрабатывать GEO параллельно с EXT.

### D4

§9.1 требует PDF, а §11 №8 называет DWG. Отчёт содержит измеренный результат PDF и явное ограничение; только решение владельца разрешает считать закрытой спорную строку приёмки.

Основание и рассмотренная альтернатива: Подмена DWG испытанием PDF дала бы ложную отметку приёмки; расширение перечня форматов без решения меняет согласованный приём.

## Risks / Trade-offs

- Размерная линейка относится к другому виду → локальная калибровка и негативные контрольные случаи.
- Незакрытый конфликт DWG → отдельное решение C24, PDF-отчёт с явным ограничением.
- Недоступна общая зависимость → контрактные проверки допускают подготовку, но не закрывают задачи реальной интеграции.

## Migration Plan

1. Согласовать схемы и владельца миграции до разработки. Добавлять только таблицы/поля своего слоя; общие таблицы изменяет владелец C01 по согласованному PR.
2. Поставить аддитивные миграции и ограниченно включить capability в разрешённой тестовой среде. Сохранить текущую авторизацию и прежние оригиналы.
3. Выполнить компонентные проверки из tasks.md на реальных зависимостях. Указать команды, версии, корпус и ссылки на отчёты в evidence.md, создаваемом при реализации.
4. При откате остановить новые операции/потребителей capability и вернуть совместимую версию приложения; не удалять исходники, аудит, принятые jobs и историю снимков. Незавершённые jobs сохраняются до совместимого возобновления.

## Acceptance boundary

На чертежах с известной опорой измерение и overlay проверены; неоднозначная опора не даёт ложного значения. Выполнен локальный PDF-бенчмарк, результат не выдан за DWG.

Готовность design/specs/tasks означает готовность плана. Все задачи остаются открытыми до реализации и проверок. Совместные сценарии настоящего сравнения, протокола, финализации, 132/132 и количественные требования общего релиза остаются в C24; никаких новых отметок выполнения при разделении не ставится.
