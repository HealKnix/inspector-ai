# Комплектность и достаточность доказательств

Владелец: P4 правила + P1 API + P2 UI. Нумерация локальная; [SRC-x.y] указывает задачу исходного объединённого change, а не её текущий статус. [Карта переноса](../../SPLIT_MAP.md), [общие обязательства](../../SHARED_BACKLOG.md), [контракты](../../CONTRACTS.md).

Все задачи открыты: перенос и готовность планирования не означают реализацию. Backend/frontend/ML выполняются в рамках одного функционального change; завершение определяется его спецификацией.

## 1. Контракты и предпосылки

- [x] 1.1 Проверить зависимости ID, EXT, GEO и C05-C18; закрепить версии входных/выходных контрактов из CONTRACTS.md. Проверка: у каждой используемой сущности и миграции есть один владелец, отсутствующая зависимость явно отмечена.
- [x] 1.2 [SRC-1.2] Описать API ожидаемого состава, подтверждения и результата комплектности с nullable-оценкой и версиями. Проверка: примеры неизвестной полноты, AND/OR и причин проходят OpenAPI-валидацию.

## 2. Данные и миграции

- [x] 2.1 [SRC-2.6] Добавить PackageRequirement/Version и CompletenessResult, используя RuleVersion и Evidence из соседних слоёв. Проверка: таблицы Params/Extraction не дублируются, старые версии перечня и результата доступны.
- [ ] 2.2 Сформировать нормативный каркас по §3–6 ТЗ: словари разделов ПД, марок РД и видов ИД, базовые требования с условиями применимости и генераторами, таблица соответствия разделов Матрицы. Проверка: каркас версионируется и утверждается администратором, каждая строка ссылается на нормативное основание, `;` в исходных источниках не становится оператором автоматически.

## 3. Реализация capability

- [ ] 3.1 [SRC-2.7] Подключить capability document-completeness к общим проверкам доступа/аудиту C01 и безопасным событиям/метрикам C23. Проверка: изменение оставляет автора/версию/корреляцию, запрос чужого объекта отклонён, содержимое и секреты отсутствуют в логах; транспорт уведомлений не реализован повторно.
- [ ] 3.2 [SRC-7.1] Реализовать извлечение кандидатов ожидаемого состава из состава проекта, ведомостей, общих данных и реестров ИД; проверка: каждое предложение имеет источник и область, реестр десяти актов не объявляет полным весь объект.
- [ ] 3.3 [SRC-7.2] Реализовать версионированное подтверждение состава инспектором и правил администратором; проверка: неподтверждённый/неизвестный перечень не даёт полной комплектности, старые версии не изменяются.
- [ ] 3.4 [SRC-7.3] Реализовать AND/OR/количество/покрытие листов и областей по проверенным правилам; проверка: паспорт OR сертификат и акт AND схема обрабатываются различно, `;` не интерпретируется автоматически.
- [ ] 3.5 [SRC-7.4] Реализовать сопоставление требований с документами и актуальными редакциями; проверка: два представления не закрывают два акта, акт одной области не закрывает соседние работы.
- [ ] 3.6 [SRC-7.5] Реализовать девять статусов стадий, сценарии загрузки и отсутствие оценки при неизвестном основании; проверка: все сочетания стадий и частичности совпадают с CO-03, «есть три файла» не превращается в FULL.
- [ ] 3.7 [SRC-7.6] Реализовать применимость и gate доказательств для каждого параметра; проверка: NOT_APPLICABLE/MISSING_EVIDENCE/NOT_COMPARABLE/CLARIFICATION_REQUIRED разделены, причины сохраняются, парное сравнение разрешается правилом.
- [ ] 3.8 [SRC-7.7] Реализовать объяснимый результат комплектности с источниками, выбранными документами и незакрытыми частями; проверка: счётчики следуют всем требованиям, а не текущей странице таблицы, ни один пропуск не увеличивает число нарушений.
- [ ] 3.9 Реализовать детерминированный вызов расчёта для снимка/версии состава и выбранного множества требований, а также событие подтверждения состава. Проверка: новые входы дают новый результат, прежний остаётся, INC может вызвать функцию без обратной зависимости.

## 5. Проверки и доказательства готовности

- [ ] 5.1 [SRC-11.2] Прогнать комплектность на подтверждённом перечне и реальных выходах ID/EXT/GEO. Проверка: пропуски, старые редакции и дубли представлений не дают FULL или нарушение; общий протокол остаётся C24.
- [ ] 5.2 [SRC-11.9] Проверить конкуренцию подтверждения состава и расчёта, повтор доставки и неполные evidence. Проверка: каждый результат связан со своей версией, причины не исчезают, история неизменна.
- [ ] 5.3 Проверить самостоятельный результат на реальных зависимостях: На утверждённом перечне рассчитаны полнота и gate с доказательствами причин; пропуски не увеличивают нарушения. Изменение версии даёт новый результат без изменения истории; сравнение/протокол для локальной приёмки не нужны. Проверка: evidence.md содержит команды, версии, результаты и ограничения; mocks не используются как доказательство закрытия реальной интеграции.
- [ ] 5.4 Выполнить применимые проверки существующего репозитория для изменённых частей (тесты, typecheck, build) и проверку OpenSpec. Проверка: результаты записаны в evidence.md, auth не сломан, отложенные обязательства C24 перечислены без отметки выполнения.
