## Why

Наличие нескольких файлов не доказывает полноту документации. Нужна оценка по подтверждённому составу и областям работ, отдельно от предметных нарушений.

Источник требований — [итоговый PDF и приложения](../../../docs/requirements/SOURCES.md). Исходный объединённый change сохранён в [истории](../../superseded/2026-09-17-add-document-ingestion-and-completeness/proposal.md); перенос требований и задач — [SPLIT_MAP.md](../../SPLIT_MAP.md).

## What Changes

- Версионированный ожидаемый состав и подтверждение инспектором/администратором.
- Применимость, AND/OR, количество, листы и области работ.
- Статусы стадий, сценарии загрузки, проверка достаточности источников и объяснимый UI.

## Impact

backend/modules/completeness и PackageRequirement/Version, UI перечня и причин, API подтверждения состава.

Предлагаемый владелец: P4 правила + P1 API + P2 UI. До завершения требуются: add-document-identification, add-document-evidence-extraction, add-drawing-geometry-analysis; общие предпосылки C05-C18 из [реестра](../../SHARED_BACKLOG.md). Подготовку по контрактам можно вести раньше реализации зависимости.

## Non-goals

Здесь нет сравнения expected/actual, подтверждения нарушений и финализации. INC вызывает этот расчёт при изменениях; сам граф инкрементальности находится в INC.

Критерий самостоятельного результата: На утверждённом перечне рассчитаны полнота и gate с доказательствами причин; пропуски не увеличивают нарушения. Изменение версии даёт новый результат без изменения истории; сравнение/протокол для локальной приёмки не нужны.
