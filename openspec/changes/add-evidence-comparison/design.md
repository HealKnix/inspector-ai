## Context

Базовые 11 задач реализованы и подтверждены историческим evidence. На 26.09
`identified-groups.ts` уже применяет контексты редакций ID, а протокол читает
сохранённые группы. `normalizeUnit` обрабатывает алиасы, но `unitsCompatible`
не переводит мм↔м и допускает отсутствующую с одной стороны единицу с warning;
слияние одинаковых unitless-значений также может скрыть недостаточность основания.
Продолжение устраняет эти ограничения, не реализует базовый конвейер заново.

## Goals / Non-Goals

**Goals:** проверяемое численное сравнение с происхождением единиц, явной
конверсией и политикой точности, сохранение неизвестности.
**Non-Goals:** угадывание норм, исправление оригинального OCR, выбор редакции
в обход ID, составные/GEO/EVENT-операторы и переутверждение старых протоколов.

## Decisions

### Сравнение — спека версии правила, а не код параметра

`rule_versions.comparison` (колонка существует со схемы EXT) хранит проверенную
JSON-спеку. Новая версия правила обязана нести comparison заново: спека
неизменяема внутри версии, как и план. Новая approved-версия меняет
ruleset fingerprint → переизвлечение и пересборка групп идут существующим
механизмом EXT без отдельного контура доставки.

Основание и альтернатива: спека как часть версии правила сохраняет
аудируемость «чем сравнивали» наравне с «что искали». Отдельная таблица
сравнений дублировала бы жизненный цикл версии.

### Реализованный набор операторов покрывает ограниченный скалярный срез

- `equals` — нормализованное равенство текста; числа сравниваются численно
  («несоответствие отметки», P009 ±0.000);
- `numeric_delta` — `|actual − expected| ≤ tolerance_abs` или
  `≤ tolerance_pct · |expected|` (P002 «дельта > 1%»);
- `no_decrease` / `no_increase` — численное порядковое сравнение; классы
  материала требуют отдельной утверждённой интерпретации, не строки как числа;
- `threshold` — нормативная граница на само значение без пары
  (P048 «проступь < 300 мм»).

Наличие этих операторов не доказывает покрытие всех триггеров Матрицы.
Порог включается в правило после проверки применимости и источника.
Предложение LLM не обходит gate регрессий C05/C18.

### Вердикт вычисляется при сборке группы и персистится

`rebuildGroups` после формирования members вызывает чистую функцию
`evaluateGroup(members, spec)` и сохраняет результат в
`evidence_groups.verdict` вместе со снимком спеки и версией движка
сравнения. Чтение вердикта не пересчитывает его — ответ API отражает
сохранённое состояние цикла.

Основание и альтернатива: вычисление на чтении не оставляет
аудируемого «что было показано», а персист в момент сборки фиксирует
вердикт вместе с ruleset_hash той же транзакции.

### Стадия — снимок на момент извлечения; протухание чинится циклом

`extractions.stage` остаётся снимком классификации на момент цикла.
`recover()` дополнительно ставит новый цикл извлечения артефакту, чья
последняя succeeded-классификация дала стадию, отличную от сохранённой в
извлечениях (`IS DISTINCT FROM`). После переизвлечения снимок сходится с
классификацией — повторных циклов не возникает. Переисполнение дёшево:
извлечение — regex/таблицы по уже сохранённому артефакту.

Основание: джойн «живой» классификации в сборке групп разорвал бы
инвариант снимка и оставил бы список извлечений с устаревшей стадией —
рассинхрон ролей группы и строк UI.

### Исходы вердикта — явные, без выдумывания

`match`, `discrepancy`, `expected_missing`, `actual_missing`,
`expected_ambiguous`, `actual_ambiguous`, `not_comparable`,
`no_comparison`. Отсутствие источника стадии (`expected_missing`/
`actual_missing`) — легитимный исход «источник не передан», а не
нарушение; `ambiguous` стороны сохраняет альтернативы для инспектора;
несовместимые единицы дают `not_comparable`, а не численный mismatch.

### Область сравнения и текущая интеграция

Используется уже существующий ID snapshot: контексты области/периода,
подтверждённые редакции и `resolved_input_hash`. Роль expected/actual не
выводится заново только из стадии; allowedStages правила и blockers ID
сохраняются. Разные контексты не сливаются. Протокол получает предварительный
вердикт и фиксирует его собственным снимком; решение инспектора остаётся
отдельным. Старое описание пустого scope относится только к первому срезу.

### Единицы, числа и преобразование

Raw-значение/единица неизменны. Дополнительное нормализованное представление
содержит размерность, canonical unit, источник единицы и точное преобразование
по версионированному разрешённому справочнику. Мм↔м и м²↔см² преобразуются
с соответствующими степенями; несовместимые размерности отвергаются. Единица
из заголовка допустима только с локатором её применимости к данной ячейке.
Отсутствующая единица не наследуется от другой стороны; безразмерность должна
следовать из паспорта. «25 %» и «0,25» сравнимы только при явном представлении
доли в правиле, а не через универсальный эвристический множитель.

### Точность и неопределённость

Правило закрепляет допустимость abs/pct, нулевой expected, округление и
семантику границ. Машинный EPSILON не считается предметным допуском.
Для десятичных величин используется детерминированная арифметика; выбор
decimal или scaled integer фиксируется при реализации схемы, без смены
публичного значения raw. Неразобранное OCR `1/l/I`, знак, десятичный разделитель
или конфликт единиц остаются альтернативами, если источник не подтверждает
одну интерпретацию. Confidence не переводится в точность измерения. У GEO
интервал/погрешность учитывается только при реально предоставленном основании;
пересечение границы неопределённым значением не даёт достоверного mismatch.

### Версионированный след вычисления

Пара сохраняет исходные и приведённые значения, единицы, conversion-policy,
допуск/округление, причины unknown и locators. Новая версия движка/policy
включается в fingerprint и публикуется через существующий fencing. Старые
записи читаются в прежней версии без придумывания отсутствующей трассы.

## Risks / Trade-offs

- [Строгие единицы уменьшат число сравнимых пар] → показать причины и
  исправлять источник/правило, не сохранять прежнее угадывание.
- [Скрытая ошибка округления на пороге] → граничные decimal-регрессии с
  независимыми ожидаемыми результатами.
- [Повторная интерпретация исторических ответов] → новый цикл/версия,
  неизменность опубликованного протокола и backward-compatible чтение.

## Migration Plan

Ввести аддитивную версию политики и результата; сохранить старые читаемые
пары и 11 исторических checks. Активировать новую политику только у прошедших
regression-gate правил. Проверить старый/новый worker, смену Run и откат
активной версии для следующих расчётов. План этапов — execution-plan.md.
