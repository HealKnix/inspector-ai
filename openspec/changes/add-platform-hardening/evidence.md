# HARD — доказательства первого этапа

Дата: 27.09.2026. Выполнены задачи 1.1, 1.3 и 1.4 — 3/18 полного HARD change. Подтверждён gate HARD-decisions: решения и неизвестные по правам, данным, среде и восстановлению разделены. r8 прошёл установку, функциональный smoke 91/91 с manifest binding, независимый clean load 9/9, ingress proof 19/19 и повтор bootstrap. Все шесть gates первого этапа подтверждены; 21/115 задач шести связанных changes выполнены. Это не завершение полного HARD, OFF или ТЗ.

## Изоляция, повтор установки и границы OFF

После прежнего исчерпания диска пользователь запустил Docker: Engine 29.1.2 отвечает. На момент восстановления координатор зафиксировал около 4.6 GB на C и точечное удаление трёх старых временных dind volumes. Позднейшая отдельная очистка отклонена автоматической проверкой разрешений; соответствующие ресурсы сохранены. Очистка не входит в критерии раннего gate и не отменяет полученные результаты.

Причина сбоя RabbitMQ в r4 установлена: root healthcheck после стартового `chown` создавал cookie с uid 0 и mode 0400. Исправленный запуск через `su-exec rabbitmq` дал три последовательных health PASS на реальной internal network, cookie `100:101/0400`. В r5 отдельно выявлено отсутствие публикации host-порта при подключении только к internal networks Docker 29. В r8 frontend подключён к отдельному ingress bridge; loopback доступен, fail-closed guard блокирует исходящие IPv4/IPv6 и внешний DNS, Nginx не может менять firewall, использовать raw sockets или получать новые привилегии.

Установка r8 использовала уже присутствующие точные image IDs, а [независимый clean load](../../../docs/offline/evidence/2026-09-27-r8-clean-load.json) отдельно подтвердил 9/9 совпадений в пустом Engine 29.1.2 без сети и registry access; hash архива `dd0b39ee198c6720ff84fe154eb45c7d23d8c632c254f9d155ffb1a44325cc83`. [Статический/runtime-отчёт](../../../docs/offline/evidence/2026-09-27-r8-static-and-runtime.json) фиксирует 15/15 файлов, девять образов, восемь новых томов и 14 контейнеров: 12 running, из них 11 Docker health PASS и validator без healthcheck; два одноразовых контейнера exit 0. Validator проверен функциональным приёмом. Приложение запускалось на новых томах host daemon; полный runtime внутри пустого daemon не заявляется.

[Ingress proof](../../../docs/offline/evidence/2026-09-27-r8-ingress-proof.json) содержит 19/19 PASS на точном frontend image из manifest r8: положительные контроли IPv4/IPv6/DNS, host loopback и backend:3000 доступны, лишние адреса/порты и внешнее DNS закрыты, необходимые capability сняты, без права начальной настройки firewall запуск отклоняется.

[Повтор установки](../../../docs/offline/evidence/2026-09-27-r8-installation-repeat.json) завершён `2026-09-27T07:37:55.724Z`. [Снимки до](../../../docs/offline/evidence/2026-09-27-r8-replay-before.json) и [после](../../../docs/offline/evidence/2026-09-27-r8-replay-after.json) совпадают по manifest/catalog hashes и устойчивым IDs/counts: 7 пользователей, по 3 объекта/назначения/процесса/Run/файла/parse artifact, 132 строки матрицы, 13 версий, 1 framework set. Администратор и событие восстановления каталога остались в одном экземпляре; установщик подтвердил `restored=false`, `identical=true`. Файл секретов неизменен, его содержимое и fingerprint в evidence не раскрываются. Новые auth sessions от входа сознательно не относятся к устойчивым сущностям.

Все шесть gates первого этапа подтверждены. Полная задача OFF 4.1 остаётся открытой до сетевого журнала startup/smoke, независимо от раннего gate: раздельные доказательства firewall/изоляции и HTTP/DNS-пробы не выданы за такой журнал. Новая установка не заменяет промышленный backup/restore, а synthetic runtime smoke — предметную приёмку 132 правил или H/F.

## Неподтверждённые требования

TLS 1.3, шифрование каждого класса данных и управление ключами целевой площадки не приняты. Промышленные backup/PITR, хранение 30 дней, RPO≤15 минут, RTO≤1 часа, IDS/DDoS и длительный SLA не подтверждены. Новые полномочия курации, публикации моделей, расширенной верификации и экспорта не считаются утверждёнными. Их отсутствие явно зафиксировано в карте решений и остаётся работой соответствующих задач HARD и предметных модулей.
