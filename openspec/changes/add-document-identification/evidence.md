## Что доказывают проверки

- АОСР №52 сохраняет собственные номер/дату по QName-пути; ссылки на РД, номера приложений, оба `edition` и `Signed` не подменяют собственные реквизиты и утверждение.
- PDF/XML с достаточными согласованными реквизитами образуют одно логическое представление акта. Исправление конфликтных данных инспектором объединяет их в новом снимке; aliases сохраняют исходные карточки и решения. Повторное уточнение объединённой карточки применяется ко всем её исходникам.
- Выбор использует область и период работ, подтверждённое утверждение и замену; загруженная позже старая РД не вытесняет применимую. Неизвестная применимость соседней редакции и частичное пересечение периода блокируют сравнение, в том числе при ручном выборе ссылки.
- Два акта с разными периодами получают отдельные контексты. Пары ограничены стадиями утверждённого правила; ручная ссылка сама по себе не расширяет правило. Полнота считает логические документы, а покрытие области требует её подтверждения.
- Сквозной сценарий выполняет реальные ID/EXT/VER сервисы: акт PDF/XML и две РД → подтверждение → сравнение с первой РД → решение инспектора → уточнение периода → новый Run с отдельными ParseArtifact → сравнение со второй РД → новый протокол → финализация и повторное чтение. Старые цитаты, источники и решение остаются прежними.
- Транзакции отклоняют чужой объект, неправильную роль, PARSING/FINALIZED, активную обработку, устаревший Run/карточку и иной payload с прежним ключом. Конкурентные применения сохраняют единственный новый расчёт. Повторная доставка, истёкший lease и поздняя публикация worker не меняют текущий результат.
- Повтор машинной идентификации сохраняет решения инспектора. Любая новая selection того же Run инвалидирует все участвующие версии карточек. Точный прежний снимок доступен по Run + resolved_input_hash и открыт только для чтения.
- Совместимые PAR-результаты проходят проверку JSON/schema, source/artifact SHA-256, pipeline fingerprint и всех изображений. Повреждённые или непроверенные результаты не копируются как готовые; обычный PAR/cache выполняет последующую обработку. Новый Run всегда получает собственные записи артефактов.
- БД запрещает изменение снимков, кандидатов, уточнений, исходных частей, версий групп и источников находки. Foreign keys проверяют принадлежность snapshot/Run/объекту. Старые данные не пересчитываются миграцией; для legacy-находок без снимка выдаётся `historical_evidence_not_recoverable`.
- UI проверен на несохранённые изменения, пакет только изменённых полей, потерю ответа/повтор, 409, deep links, историю и точный artifact + Run. Находки и полностью проверенные параметры считаются отдельно; один неразрешённый контекст не даёт полного покрытия параметра.

## Границы доказательства

Интеграционные tests используют синтетические ответы парсера и локальный `/health`; PostgreSQL, RabbitMQ, хранение, HTTP, транзакции и предметные сервисы настоящие. Это доказательство выбора источников, долговечности и истории, а не качества OCR/LLM на производственном корпусе. Ранее выполненная проверка 18 XML приведена ниже как отдельное историческое свидетельство классификации.

Разделение сборных PDF, частичная замена листов, распознавание подписей/печатей, калибровка LLM, качество всех 132 правил и полный граф/производительность INC не заявляются выполненными. Несогласованные связи остаются явными блокировками; нет перехода к сравнению «все ПД против всех РД/ИД». В протоколе может быть несколько неразрешённых контекстов одного параметра, требующих уточнения состава/связей.

Миграция и реализация относятся к существующему change `add-document-identification`; исходные более широкие задачи разделов 1–5 остаются открытыми. Установка и запуск нового контура требуют обычного deploy миграции и пересборки workers; локальный `dev:all` включает extraction worker.

### Выявленные ограничения и восстановление

1. **Очередь:** в исходном пакетном прогоне четыре задания завершились `models_not_ready_timeout`, три из них при `attempt=0`. Deadline ожидания моделей сохранялся после восстановления их готовности, пока другой файл занимал consumer; `recover()` завершал ожидающие задания без новой проверки готовности. Исходные снимки сохранены до последовательных повторов.
2. **Длительные PDF:** лимит одной попытки парсера — 600 с, два CPU-потока. PD-1 продолжался с checkpoint 20, затем 33 страниц. RD-2 сначала продолжился с 14 страниц; после остановки всех контейнеров стенда — с 22 страниц и `worker_lease_expired`. Этот цикл исчерпал три попытки на 32/34 страницах (`parser_timeout`); снимки сохранены до дополнительного явного повтора, завершившего оставшиеся страницы. Всего подтверждены пять явных API-повторов: по одному ID-1, ID-2, PD-1 и два RD-2. Последующий успех не отменяет первоначальные технические отказы.
3. **Прерывание окружения:** между наблюдениями 18.09 21:05 UTC и 19.09 10:27 UTC остановились существующие контейнеры стенда. У проверенных parser/backend/postgres `OOMKilled=false`; причина остановки не установлена. Прежние контейнеры запущены через `docker start`, без пересборки или миграций. Общее календарное время прогона не является измерением производительности.
4. **Приём PD-2:** установленный валидатор и отдельный `qpdf --check` воспроизвели тайм-аут около 25 с для оригинала 42 729 599 байт. Это не доказывает повреждение или опасное содержимое PDF. Проверка приёма не обходилась; файл не переписывался.
5. **ID-1, потеря текста до OCR:** большая ошибочная область таблицы конфликтует с локальным текстом/штампом. Все 58 областей двух страниц обработаны как `skipped` (55 unknown, 3 graphic). Текстовый контекст пуст; текстовая LLM на таком входе не сможет прочитать видимую надпись.
6. **ID-2, потеря текста при отборе контекста:** `p1-b9` содержит native-заголовок «Протокол испытаний», `include_in_main=true`. Он доступен правилам, которые пока не распознают этот вид. В LLM-контекст он не попадает из-за якорей и позиции: выбрано лишь 6 фрагментов / 875 учитываемых символов, `truncated=false`. OCR-блоки с целью испытаний бетона также исключены. Нужно улучшить отбор семантически полезного текста и определить политику для подтверждающих протоколов; простое включение модели не исправляет текущий вход.

Приоритеты следующей работы: исправить ожидание в очереди; сохранить титулы/штампы при конфликте областей; улучшить отбор контекста; разделить технический тайм-аут валидации и содержательный отказ. Затем отдельно проверить живую LLM на реальном OCR-тексте. Это выявленные задачи, а не выполненные исправления. Разделы 1–5 OpenSpec и качественные пороги полной идентификации этим прогоном не закрываются.
