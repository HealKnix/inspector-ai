# C16. Обучение, допуск и откат

Владелец: P3 обучение, P1 реестр/deployment, P4 оценка, P2 интерфейс. ACC-method и опубликованный GOLD нужны до контрольной итерации. Полная ACC-result не блокирует разработку runner.

## 1. Воспроизводимый baseline

- [ ] 1.1 Выбрать ограниченную обучаемую компоненту по разрешённым меткам и локальному baseline-эксперименту. Проверка: записаны задача, вход/выход, лицензия весов, качество, время/память и причина выбора.
- [ ] 1.2 Зафиксировать контракт run/model registry: все версии, hashes, параметры, seed, среда, metrics и provenance. Проверка: пример записи позволяет восстановить входы и отличает обученную модель от принятой.
- [ ] 1.3 Назначить ответственного за approve/reject/deploy и правила доступа; выделить бюджет ресурсов обучения. Проверка: ML-роль без права публикации не получает его автоматически, лимиты проверяемы конфигурацией.

## 2. Train/eval и артефакты

- [ ] 2.1 Добавить аддитивный реестр обучающих запусков/моделей и хранение артефактов. Проверка: миграции сохраняют старые Run, неправильный artifact hash блокирует загрузку модели.
- [ ] 2.2 Реализовать локальный runner обучения на выбранной dataset_version. Проверка: сохранены команда/код/параметры/логи, отклоняются черновые и запрещённые входы.
- [ ] 2.3 Реализовать оценку baseline и candidate по одной методике и split. Проверка: P/R/F1/FPR и категории имеют проверяемые числители/знаменатели и связи с артефактами.
- [ ] 2.4 Подключить долговечные jobs, ограничение параллелизма и восстановление после сбоя. Проверка: повтор доставки не публикует модель дважды и обучение не превышает выделенную квоту.

## 3. Допуск

- [ ] 3.1 Реализовать проверку обязательных порогов и сравнение по категориям/отрицательным группам. Проверка: падение Recall на 3 п.п., рост FPR на 3 п.п. и отсутствующая обязательная категория блокируют полный допуск.
- [ ] 3.2 Добавить приём независимого отчёта оценщика с версиями и hashes без импорта hidden GOLD. Проверка: отчёт для другой модели/датасета отвергается.
- [ ] 3.3 Добавить ручной approve/reject с ответственным, временем и основанием. Проверка: окончание runner не переключает модель; неуполномоченный пользователь и stale-решение отклоняются.
- [ ] 3.4 Сделать экран сравнения baseline/candidate с ограничениями и решением. Проверка: высокий сводный F1 не скрывает регрессию отдельной категории.

## 4. Выпуск и rollback

- [ ] 4.1 Подключить выбор принятой model_version при создании Run. Проверка: активный Run сохраняет свою модель при переключении указателя для новых запусков.
- [ ] 4.2 Реализовать staged загрузку принятой модели с integrity/readiness и smoke до переключения. Проверка: неполные веса и ошибка загрузки оставляют предыдущую модель рабочей.
- [ ] 4.3 Реализовать ручной откат с причиной, аудитом и сохранением обоих артефактов. Проверка: новые Run используют предыдущую версию, старые протоколы и метрики не изменяются.

## 5. Реальная итерация

- [ ] 5.1 Выполнить одну train/eval-итерацию на разрешённом GOLD и сохранить созданные веса/адаптер. Проверка: сторонний оператор воспроизводит результат по инструкции с зафиксированными ограничениями детерминизма.
- [ ] 5.2 Продемонстрировать отказ в допуске регрессирующей модели и успешный rollback принятой. Проверка: evidence содержит метрики, решения, версии до/после и сохранность истории.
- [ ] 5.3 Передать OFF пригодные веса/лицензии и REP измерения, выполнить применимые тесты/typecheck/build. Проверка: поставка ссылается на реальные артефакты, а не локальные пути разработчика.
