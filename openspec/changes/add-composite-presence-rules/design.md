## Context

Мотивация — [proposal.md](proposal.md). В `comparison-contract.ts` есть пять скалярных операторов; `identified-groups.ts` уже разделяет области/редакции и блокирует неподтверждённые пары. COM имеет AND/OR ожидаемых документов, но не проверяет ветви предметного параметра. В Матрице P004 связан с изменением габаритов без корректировки ПД, P003 — с полезной площадью/техническими зонами, P039 — с исключением дренажных мероприятий. Их нельзя сводить к одному regex или наличию любого файла.

## Goals / Non-Goals

**Goals:** расширить существующий evaluator ограниченным деревом правил и воспроизводимой трассой по доказательствам. **Non-Goals:** произвольный исполняемый код в JSON, новая очередь, самостоятельный CV и повторное построение комплектности.

## Decisions

### Ограниченное типизированное дерево

Узлы AND/OR соединяют листья скалярного сравнения CMP, наличия элемента или подтверждённого GEO-результата. Применимость и идентификатор области проверяются до вычисления ветвей. Глубина, число узлов и уникальность идентификаторов ограничены; произвольные выражения/JavaScript запрещены. План проходит версионированную валидацию C05/C18. Альтернатива «код по parameter_code» отвергнута: она затрудняет объяснение и версионирование оснований.

### Неопределённость сохраняется до результата

Внутренние значения ветви: условие доказано, опровергнуто, неизвестно; неприменимость учитывается отдельно по паспорту. Для AND ложная доказанная ветвь определяет false, все true — true, остальное unknown; для OR true определяет true, все false — false, остальное unknown. Неиспользованные ветви остаются видимы с причиной. Преобразование в существующий verdict выполняет один адаптер: unknown не даёт match/discrepancy. Это техническая логика выражения, не новые решения инспектора.

### Наличие имеет ограниченную область доказательства

Положительный факт требует локатора и связи с элементом/областью. Для вывода об отсутствии нужны подтверждённая применимость, полный релевантный набор источников и проверенная область просмотра; `no_evidence`, провал OCR или отсутствие файла дают неизвестность. Поиск только по слову и «в списке файлов не найдено» отвергнуты как доказательство отсутствия конструкции. Когда ветвь проверяет исключение из РД предусмотренного ПД мероприятия, обе стороны и их редакции фиксируются.

### Расширение существующего pipeline

Дерево и версия evaluator входят в ruleset fingerprint. EvidenceGroup хранит дерево исполнения, использованные ветви, источники и resolved-input hash. Поздний worker не публикует ответ для изменённого Run/правила. Геометрическая ветвь читает версионированный GeometryResult через контракт GEO; отсутствие масштаба остаётся unknown. UI показывает определяющие ветви с переходами в существующий viewer; протокол получает предварительный вывод, решение остаётся у инспектора.

### Зависимости и приёмка

Этап A `add-reviewed-matrix-release` предоставляет ранний контракт и gate регрессий. CMP поставляет скалярные операции, единицы и неопределённость; ID/EXT — выбранные источники. Первые текстовые ветви выполняются без GEO; готовность GEO требуется только для их пространственных листьев. P003/P004/P039 — кандидаты первых реальных регрессий, конкретные условия берутся из утверждённых паспортов. Профиль 51 COMPOSITE/8 PRESENCE из старой карты перепроверяется при формализации; это не обязанность написать 59 независимых движков.

## Risks / Trade-offs

- [Неполные источники выглядят как отсутствие] → отдельное основание полноты и тесты unknown.
- [Смешение двух конструкций/периодов] → одинаковый подтверждённый контекст обязателен для всех связанных ветвей.
- [AND/OR выбран по предположению] → паспорт с разложением триггера и предметным основанием обязателен до approve.
- [Зависимость от GEO тормозит весь оператор] → ранняя текстовая приёмка отдельно, пространственная ветвь блокируется адресно.

## Migration Plan

Добавить новую версию схемы плана аддитивно; существующие скалярные планы читаются прежним исполнителем. Включить новые планы только после контрактных, PG/RabbitMQ и реальных evidence-регрессий. Откат выбирает прежний опубликованный ruleset; сохранённые ветви и исторические протоколы остаются доступны.
