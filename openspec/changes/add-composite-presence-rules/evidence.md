# C07: ограниченный составной оператор, 28.09.2026

Реализован этап B (2.1–2.4) для AND/OR со скалярными листьями **одной существующей EvidenceGroup**. Это техническая готовность оператора; никакое правило Матрицы этим отчётом не утверждено. Остальные задачи change остаются открытыми.

## Контракт и исполнение

- `backend/src/modules/extraction/comparison-contract.ts`: аддитивный `kind: composite`, `schema_version: 1`, `root`. Узел AND/OR содержит уникальный `id`, `kind: and | or`, `children`; scalar-лист содержит `id`, `kind: scalar`, `comparison` существующего CMP. Корень — AND/OR, глубина до 6, узлов до 64, детей от 2 до 8, длина id до 64. Неизвестные поля/виды/версии, повтор id/объекта, цикл и превышения отклоняются. Вложенный composite внутри scalar запрещён. Старый `{kind: equals}` остаётся допустимым скалярным контрактом.
- Версии: `comparison-engine-v4`, `composite-scalar-v1`. `regressionEngines` включает composite; fingerprint отчёта допуска меняется. Поддержанная схема не принимает presence/geometry/event и не содержит произвольного кода.
- `composite-comparison.ts` вызывается из прежнего `evaluateGroup`. Каждый лист вызывает тот же CMP evaluator на отдельной копии членов группы; арифметика и нормализация не дублируются. Проверены точные единицы, границы и интервалы неопределённости внутри и вне дерева.
- AND: доказанная ложная ветвь даёт false, все true дают true, остальное unknown. OR: доказанная истинная ветвь даёт true, все false дают false, остальное unknown. Адаптер оставляет существующие verdict: true → match, false → discrepancy, unknown → not_comparable. Это предварительное вычисление, не решение инспектора.
- Общая применимость передаётся сервером отдельно от правила: `applicable | not_applicable | unknown` и основание. READY источников не доказывает предметную применимость. Неизвестная/неприменимая оценка или недостающий контекст оставляют все ветви unknown и `evaluated: false`.
- `CompositeEvaluationContext` связывает `context_id`, `scope_key`, `period_key`, reference/actual document+revision, применимость и её основание. Каждый член обязан совпасть с контекстом/областью/периодом и редакцией своей стороны. Чужая или недостающая связь блокирует дерево до сравнения.
- `GroupVerdict.composite` хранит версию, контекст, `resolved_input_hash`, полное дерево, исход/применимость/evaluated/reasons/определяющие дочерние узлы. Лист сохраняет скалярный verdict и исходные extraction/file/artifact/document/revision IDs с локаторами. Исполняются все доступные листья; неизвестная ветвь OR остаётся видимой даже при истинном итоге.
- `compositeSemanticBasis` выделяет семантическое основание для carryover: версии, применимость/основание, контекст, исходы и причины ветвей. Новые per-Run IDs, timestamp и технический input hash не подменяют изменение предметного основания. Подключение helper к fingerprint протокола проверяется владельцем общего pipeline отдельно.

## Серверная регрессия и допуск

`matrix-regression.ts` исполняет дерево через существующий EXT/CMP. Паспорт требует ветвь `operator: composite` с id корня, текущую версию, основание AND/OR и отдельные `operator: comparison` с id каждого scalar-листа. Каждая обязательная категория положительного/отрицательного/граничного/неопределённого случая проверяется прежним механизмом; разрешённые явные исключения сохраняются. Недостающие версии, ветви, категории или основание блокируют отчёт.

Вход регрессии аддитивно принимает контекст и привязку document/revision/context каждого источника. Ожидания для composite обязательно перечисляют **все** узлы в порядке обхода: id/result/evaluated, вместе с общим исходом. Сервер вычисляет это сам и сравнивает с независимой меткой. Подмена одной ветви не проходит даже при неизменном общем verdict. Отчёт сохраняет полную фактическую трассу, hashes входов/правила/паспорта и версий.

Расширены только ограниченные размеры существующего паспорта/fixtures: до 65 паспортных ветвей и 260 fixtures (64 узла плюс extraction, четыре категории). Новый каталог/очередь/механизм approve не создан.
