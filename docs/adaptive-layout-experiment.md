# Проверка Paddle layout перед адаптивным OCR — 18.09.2026

**Решение: автоматическое исключение графики не включать.** Закреплённый
PP-DocLayout_plus-L различает абзацы и многие планы, но на контрольном корпусе
пропускает отдельные таблицы/подписи и может считать целую исполнительную
схему таблицей. Условия перехода из [утверждённого плана](../openspec/changes/add-document-parsing/adaptive-ocr-plan.md)
не выполнены. VLM не подключалась. Региональный OCR и режим «Области» остаются
следующим условным шагом, а не объявляются работающей функцией.

## Воспроизводимость

- 31 изображение: 20 страниц разрешённого PDF, паспорт, исполнительная схема,
  растровые PDF-копии текстового листа и плана, 7 синтетических PDF
  (таблица, mixed, повреждённая ToUnicode, CropBox с Rotate 0/90/180/270).
- Ожидаемые области вручную размечены **до inference** по оригинальным
  страницам. Это укрупнённые прямоугольники для проверки разделения областей,
  не пиксельный эталон и не основание заявлять общую точность модели.
  Синтетические координаты получены из геометрии генератора.
- Финальная разметка: SHA-256
  `cf34d60b7e1921503f327a6a4d7af009c685e2911ecbc1b0e8fd0747cd78100d`.
  Linux manifest:
  `2ac057565ef84273464649f0bc39df2c1ae0699e43293e596e1c1a2aa1d66aa3`.
- PaddleOCR 3.7.0, PaddleX 3.7.2, PaddlePaddle 3.3.1, NumPy 2.3.5,
  Pillow 12.3.0; три файла модели проверены по production model-lock.json.
- Только `LayoutDetection.predict` на исходных BGR-пикселях: без масок,
  OCR, определения ориентации, распознавания таблиц или перебора порогов.
  Параметры threshold/NMS/merge/unclip взяты из закреплённого PP-StructureV3.
  Классы image/chart не объявлялись строительными чертежами.
- Linux Docker: `--network none --cpus 2 --memory 4g --memory-swap 4g`,
  модели и код read-only. Выход находится на D:, вне Git. Один predictor
  переиспользован на всех страницах; новые модели не скачивались.

Команда и manifest описаны в [experiments/README](../backend/document-parser/experiments/README.md).
Генератор [layout_fixtures.py](../backend/document-parser/experiments/layout_fixtures.py)
не содержит реальных документов. Исходники, raw JSON, PNG с границами,
ручная разметка и HTML-отчёт остаются в локальном каталоге
`tmp/adaptive-layout-probe-20260918` рядом с репозиторием.

На ранее проверенной исполнительной схеме почти весь лист классифицирован как table, отдельно найден только seal. Правило маршрутизации отправило бы план в распознавание таблиц. |

Постпроцессор регионального маршрута не внедрялся после провала предыдущих условий. Высокая уверенность неправильного table не решает семантическую ошибку.              |
| Текущие CPU/RAM-ограничения соблюдены                           | Выполнено для layout-only: 31/31, выход 0, без OOM и таймаута. Это не замер полного OCR-пайплайна.                                                                                                                                                                |

Дополнительные наблюдения: синтетический прямоугольный план с линиями принят
за table, хотя текстовая вставка рядом выделена отдельно. На CropBox+Rotate90
таблица найдена, заголовок пропущен. Это проверка детекции по отображаемому
изображению; она не доказывает корректность ещё не внедрённого разбора
native-таблиц или его обратных преобразований.

Паспорт: найдены обе таблицы, шапка и заключение. Область рукописных подписей
определена как image, что также требует осторожности: внутри неё есть печатные
имена. Прямое исключение любого image не гарантирует сохранение пояснений.

Полное время также включает импорт, проверку хешей и запись изображений;
RSS worker не является суммой памяти всех процессов контейнера. Cgroup
ограничивает контейнер целиком. Модельные confidence не выдаются за точность
текста, таблиц или общего корпуса. Скрытая приёмка C24 не выполнялась.

## Что выпускается независимо от результата

Удаление пустых OCR-текстовых фрагментов с сохранением настоящих пустых ячеек;
сохранение прочитанного текста при отклонённой структуре таблицы; исправление
readiness дочернего процесса; проверка всех checkpoints перед продолжением;
сохранение и объяснение прогресса; конечное ожидание моделей в 300 секунд.
Оригиналы и старые артефакты не удаляются. Прежний OCR-маршрут пока остаётся
рабочим: этот выпуск не обещает автоматический пропуск чертежей.

Для следующей проверки нужно сначала решить пропуски таблиц/подписей и
ошибку «чертёж как таблица», затем повторить условия на отдельной контрольной
части корпуса. Снижение порога или произвольное исключение больших таблиц
не считается доказанным решением; VLM остаётся отложенной.
