# Решения и границы первого этапа

Дата: 27.09.2026. Этот реестр реализует HARD-decisions; промышленная защита и восстановление остаются отдельными проверяемыми этапами HARD. Источники: [ТЗ и приложения](../requirements/SOURCES.md), [подтверждённая политика доступа](../../openspec/CONTRACTS.md), действующие guards/services и [полный план](../../openspec/RELEASE_PLAN.md).

## Runtime

Поставочный профиль использует **Node.js 24.16.0** для API, workers, миграций и deployment CLI в соответствии с §1.5 ТЗ. Bun 1.4.2 остаётся менеджером workspace-зависимостей и инструментом сборки. Совместимость проверяется через targets `node-runtime`/`node-migrate` существующего backend/Dockerfile; прежние dev/Bun targets сохранены. Использование Node не требует отклонения от ТЗ. Совместимость подтверждена build/typecheck/применимыми tests и первым функциональным smoke поставочного r8: Node v24.16.0 у API и четырёх workers, реальные очередь/парсер/артефакт. Задачи HARD 1.3/1.4 выполнены; [HARD evidence](../../openspec/changes/add-platform-hardening/evidence.md) фиксирует предел вывода. Усиленный smoke, повтор bootstrap и независимый clean load архива продолжаются в OFF; это отдельные критерии его начального gate.

| ClamAV                         | Отдельный volume сигнатур; в release без фонового freshclam                                            | Проверенный снимок/дата/версия, повторное сканирование после аварии по правилам приёма                                                          |

| Backup                         | Реальный промышленный механизм ещё не настроен                                                         | Ежедневная база ≥30 дней + журнал изменений для RPO≤15 мин; измеренный restore≤1 ч, hashes/ссылочная целостность                                |

Внешний доступ первого локального стенда — только loopback-порт frontend. В r8 ядро подключено к `offline` с `internal: true`; только frontend дополнительно использует ingress bridge, чтобы Docker 29 публиковал host-порт 18080. Его fail-closed OUTPUT guard блокирует исходящие IPv4/IPv6 и внешний DNS; после настройки Nginx не может менять firewall, использовать raw sockets или получать новые привилегии. Доступ с хоста и блокировка внешних HTTP/DNS подтверждены первым smoke. БД/брокер/метрики не публикуются на хост; `/api/internal/` закрыт Nginx, прямые метрики требуют отдельного service token. Локальный HTTP-профиль не засчитывает TLS 1.3 промышленной площадки.

[Установка r8](../offline/evidence/2026-09-27-r8-installation-first.json) закрепляет manifest `b899ad410f1307ffe767d07c4ec2711750506534e66c912a2a29ef41db0e7692` и каталог `69a576ed1a0ef7ed91076ebc26a4ebba746072abbd7692c0f7f1d6a1fd6f9cf1`: 132 строки, 13 approved-версий для 12 параметров. Это начальный импорт разрешённого справочника и создание администратора существующей deployment CLI, не восстановление пользовательской БД и не backup/restore по RTO/RPO. Установка использовала уже присутствующие точные image IDs; повтор установки и независимый чистый импорт архива проверяются отдельно.

| Чтение истории объекта                                  | То же разрешённое чтение объекта, frozen evidence своей версии                         | AUD использует серверную проверку назначения; межобъектный журнал этим не разрешается                     |
| Технические метрики                                     | Service token, только внутренняя техническая граница                                   | Не новая роль приложения; ADMINISTRATOR/ML_ENGINEER не получают токен автоматически                       |
| Курация/публикация GOLD                                 | Подробная матрица пока не подтверждена                                                 | Нет разрешённой операции: deny; владелец решения — заказчик/владелец доступа, потребитель — GOLD этап1    |
| Обучение/допуск/публикация модели                       | ML_ENGINEER имеет заявленное назначение, но конкретные команды/область не подтверждены | Новых разрешений нет: deny; владелец решения — заказчик, потребитель — ML этап1                           |
| Ручное изменение evidence/split/супервизор              | Нужен подтверждённый контракт VER, новая роль не вводится                              | До решения deny для новых операций; текущие верификационные права не расширяются                          |
| Экспорт/межобъектный аудит                              | Доступ к объекту не равен разрешению произвольной выгрузки                             | Новые экспортные права не включены; решения до EXPORT/AUD-F принимаются отдельно                          |

Отсутствующие предметные разрешения зафиксированы как закрытые по умолчанию входы следующих этапов. Этот реестр не выдаёт предложение за согласие заказчика и не создаёт новых бизнес-ролей или enum. При реализации зависимого модуля расширение матрицы должно ссылаться на явное решение и получить проверки прямых API-запросов.

## Ресурсы и открытые эксплуатационные входы

Локальный стенд Docker Desktop: Linux/amd64, 12 CPU, около 7.36 GiB RAM по Docker info. Это диагностическая среда; факт выделения H100 целевым контейнеру здесь не проверен. Текущий parser — CPU-профиль; перевод device/CUDA принадлежит PAR, подключение H100 — OFF после него. Имя GPU не доказывает квоту/скорость; CPU fallback не становится требованием хакатона.

Оператор целевой площадки должен предоставить ingress/сертификаты, модель at-rest/ключей, backup storage, квоты GPU/VRAM, разрешённые service ACL и правила актуальности ClamAV. Их отсутствие не компенсируется фиктивной конфигурацией. На первом этапе можно проверить изоляцию, Node-совместимость и холодную установку существующего ядра; TLS/IDS/DDoS/RTO/RPO принимаются в соответствующих задачах HARD.
