# Классификация после парсинга

После публикации ParseArtifact отдельный `classification-worker` определяет принадлежность файла к ПД, РД или ИД. Он использует уже извлечённый текст; повтор классификации не запускает OCR. Ранее разобранные файлы текущего Run также подхватываются автоматически. Задания, результаты и повторные попытки сохраняются в PostgreSQL; доставка идёт через transactional outbox и RabbitMQ.

Сначала работают правила по собственному титулу, основной надписи и известным полям XML АОСР/исполнительных схем. Название папки, имя файла, марка КЖ/АР и ссылки на чужие документы не доказывают класс. При конфликте собственных признаков сохраняется неопределённый результат. Для остальных неоднозначных случаев можно включить LLM.

В модель отправляется ограниченная выборка текстовых блоков: титульные фрагменты, признаки стадии и соседние строки с идентификаторами страниц/блоков. Лимиты: 48 фрагментов, до 900 символов на фрагмент, до 18 000 символов сериализованного контекста фрагментов. Полный файл и изображения не отправляются. Сервис проверяет структуру JSON, допустимый класс и точное присутствие каждой цитаты в отправленном тексте. Предложение модели всегда помечается «Требует уточнения»: её уверенность не считается калиброванной оценкой качества.

## OpenRouter

В корневом `.env` для Docker Compose, либо в `backend/.env` для локальных процессов:

```dotenv
CLASSIFICATION_LLM_ENABLED=true
CLASSIFICATION_LLM_BASE_URL=https://openrouter.ai/api/v1
CLASSIFICATION_LLM_MODEL=qwen/qwen3.8-27b
CLASSIFICATION_LLM_API_KEY=<ключ OpenRouter>
CLASSIFICATION_LLM_RESPONSE_FORMAT=json_schema
CLASSIFICATION_LLM_TIMEOUT_MS=60000
CLASSIFICATION_LLM_MAX_RESPONSE_BYTES=131072
```

Ключ хранится только на сервере, без префикса `VITE_`. Настройки API и worker должны совпадать. В примерах LLM выключена до заполнения ключа: правила при этом работают, неоднозначные результаты остаются неопределёнными. Включение LLM разрешает отправку указанных фрагментов настроенному провайдеру.

После обновления кода и `.env` обычный запуск применяет миграции и поднимает новый worker:

```sh
docker compose --env-file .env up -d --build --wait --wait-timeout 900
```

Для локальной разработки примените миграции, соберите backend и запустите процессы из backend с общим `.env`:

```sh
bun run --cwd backend prisma:deploy
bun run --cwd backend build
bun run dev:all
```

Отдельная команда: `bun run --cwd backend classification:worker`. Healthcheck worker — порт 3003. Фоновый процесс проверяет новые артефакты каждые 5 секунд; загрузка очереди может увеличить задержку. При смене версии правил, промпта, модели или адреса провайдера интерфейс предложит повтор с текущими настройками. Он создаёт новый цикл классификации; старый результат остаётся в истории. Обновляйте API и worker вместе, останавливая старые экземпляры: worker не исполняет задания чужой конфигурации и не изменяет их результаты.

## Ollama и другие совместимые серверы

Тот же адаптер использует `POST {BASE_URL}/chat/completions`. Для локального Ollama укажите `http://127.0.0.1:11434/v1` и точное имя установленной модели; ключ обычно не требуется. Из контейнера Docker Desktop адрес хоста — `http://host.docker.internal:11434/v1`. Если сервер не поддерживает JSON Schema, явно задайте `CLASSIFICATION_LLM_RESPONSE_FORMAT=json_object`. Проверка ответа и цитат на нашей стороне остаётся обязательной. Автоматического переключения провайдера нет.

## Результаты и повторы

На странице объекта блок «Принадлежность документации» показывает вид, метод, необходимость уточнения и подтверждающие цитаты. Цитата открывает соответствующий артефакт в существующем просмотрщике. Неопределённый вид отличается от технической ошибки. Повтор создаёт новый цикл классификации с идемпотентным ключом, сохраняя результат предыдущего цикла.

- `GET /api/v1/objects/:objectId/classification` — результаты только текущего Run и последнего успешного цикла парсинга.
- `POST /api/v1/objects/:objectId/files/:fileId/classification/retry` с `{ "request_id": "UUID" }` — повтор без OCR, HTTP 202.

Доступ проверяется по назначению инспектора на объект. Таймауты, обрывы соединения, HTTP 429 и 5xx допускают до трёх попыток с задержкой. Невалидный JSON или неподтверждённая цитата завершаются технической ошибкой, без выдуманного класса. После смены Run или повторного парсинга прежний результат не публикуется как текущий.

Это реализация классификации файла. Она не создаёт логические документы и редакции, не разделяет сборные PDF, не проверяет подписи и не переводит процесс в READY. Ручное подтверждение и изменение класса с аудитом относятся к оставшейся части `add-document-identification`.

Совместимость сверена с [Chat Completions](https://developers.openai.com/api/reference/resources/chat), [OpenRouter Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [Qwen3.8 27B](https://openrouter.ai/qwen/qwen3.8-27b) и [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility).
