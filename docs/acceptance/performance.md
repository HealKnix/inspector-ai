# Стенд, границы измерений и решения

Первичный ответ организатора 21.09.2026 закреплён в [sources.json](sources.json). Для одной команды доступны максимум один физический H10080ГБ, 24 физических ядра/48 потоков, до640ГБ RAM и не менее300ГБ рабочего NVMe, Linux/Docker/NVIDIA Container Toolkit. GPU может совместно использоваться несколькими командами, поэтому80ГБ нельзя считать гарантированно свободной эксклюзивной памятью. Драйвер NVIDIA в образ не включается; совместимый CUDA runtime входит. Полный CPU fallback для H не обязателен. Удалённый API команды и внешние LLM/OCR/VLM запрещены.

Фактические OS/kernel/CPU/GPU/driver/CUDA, выделенные quota, свободная VRAM, contention, образ/digest, model/rules/matrix versions, конфигурация workers/threads, batch size, corpus hashes и cache state записываются при каждом прогоне. На текущей Windows-машине проверены инструменты методики; это не нормативный H100 benchmark. Профиль стенда не заменяет измерение доступных ресурсов.

## Таймеры и результаты

Все серверные интервалы измеряются монотонными часами. UTC используется только для корреляции событий, не для вычитания длительностей. Фиксируются start/end события, duration_ms, success/failure, очереди/повторы, количество файлов/страниц/параметров, concurrency и cold/warm. Неудачные/timeout запуски остаются в отчёте. Минимальная инженерная серия для коротких сценариев —5 повторов на одном snapshot, с отдельным cold и warm; для API нужны сырые latency samples, p50/p95/p99 и число ошибок, а не среднее из p95.

Границы каждого из15 сценариев и исходные числа находятся в строках `PERF-*` [реестра](requirements.json). Уточнения:

- Upload: первый байт, принятый сервером, → фиксация receipt/manifest и process_id. Сетевое время браузера сообщается отдельно. Превышение лимита — тест отказа, не успешная загрузка для расчёта средней скорости.
- Parse/OCR: старт обработки job → долговечная запись результатов всех страниц. Queue wait и model warmup показываются отдельно и входят в полный цикл. Нельзя считать только время вызова OCR-библиотеки.
- Полный цикл по QA H24: успешное принятие всего фиксированного набора → READY после сохранения протокола. UI/ручные действия не входят. READY без пригодных фактов или0фактически сравненных из132 отдельно обозначает неполноту, не успешное сравнение132.
- Comparison: готовый зафиксированный snapshot → сохранённые исходы всех132 параметров и evidence. Unknown/not-applicable/нет источника раскрываются отдельными счётчиками.
- Export: неизменяемый protocol snapshot → готовые доступные JSON/PDF, включая storage. Отправка в РиН — отдельный таймер до acknowledgement; H mock и F реальная передача не объединяются.
- Incremental: новое поступление durably accepted → новая READYверсия. Предыдущая версия остаётся неизменной. Сопутствующий полный rerun измеряется и не называется selective recomputation.
- NLP: готовый вход одного параметра → сохранённый факт; отдельно отOCR. CV DWG не подменяется PDF-тестом.
- API: получение сервером запроса → завершение ответа; endpoints, payload sizes, очередь, фоновые задания, distribution и failures зафиксированы. Профиль≥100 независимых авторизованных инспекторов, а не100соединений к healthcheck. Think time и смесь действий задаются до прогона.
- UX:5инспекторов, один фиксированный протокол132/14, от открытия READY до реально сохранённых всех решений/завершения.≤3осознанных действия на нарушение по QA H28; auth/open object не входят, zoom/pan/scroll не входят лишь если не нужны для скрытых обязательных полей. Для каждого участника время/действия/ошибки отдельно.

§11 имеет основное «не более» и отдельный столбец допуска. Отчёт сохраняет `base_budget`, `table_tolerance`, `within_base`, `within_base_plus_tolerance`; запрещено молча заменить200мс на250мс или30мин на40мин. До отдельного решения прохождение основного бюджета подтверждает выполнение, превышение основного при попадании в допуск отмечается `TOLERANCE_DECISION_REQUIRED`. Более строгое явное UX требование§9.3/QA H19≤30мин сохраняется. SLA99.9% требует согласованного длительного окна; короткий uptime/нагрузочный тест его не подтверждает.
