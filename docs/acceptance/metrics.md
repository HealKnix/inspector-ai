# Расчёт метрик и контрольные примеры

Версия методики `ACC-method-2026-09-27.1`. Функции в [metrics.mjs](../../scripts/acceptance/metrics.mjs) независимы от реализации Inspector AI; контрольные примеры запускаются Vitest. Они не оценивают текущую модель на реальном корпусе.

До запуска оценщик фиксирует universe атомарных контрольных точек, обязательные доказательства, object/section/difference_type/case_type, версии, нормализацию и исключения. Предсказания не определяют знаменатель и не могут исключать неудобные случаи. Дубли atomic keys — ошибка входа. Полная группа проходит проверку только при правильности каждого обязательного источника; partial evidence не даёт частичный TP. Экспортная атомарность QA H17 согласуется с §14: одна атомарная точка соответствует одной evidence_group, групповая подача разворачивается по locations с полным комплектом доказательств.

## Нормализация и OCR

Строка переводится в Unicode NFC; повторный whitespace заменяется одним пробелом, внешние пробелы удаляются. Регистр игнорируется только у полей с заранее заданной `case_insensitive=true`. Шифр/редакция/номер по умолчанию чувствительны к регистру. Цифры, знак, единица, пунктуация и десятичные разделители не выбрасываются. Символ — Unicode code point, а не UTF-16 code unit. WER использует слова после той же whitespace-нормализации.

Для OCR в знаменатель входят только печатные зоны не менее 300 dpi, зафиксированные до запуска. Рукописные, недостаточный dpi и заранее признанные нечитаемыми зоны имеют premarked exclusion и `LOW_QUALITY/ABSTAIN`; отчёт показывает их число/долю. Нельзя назвать зону нечитаемой после плохого предсказания. На eligible зоне abstention считается пустым распознаванием: её символы остаются в знаменателе и дают удаления.

- `CER = ΣLevenshtein(reference, prediction) / Σlen(reference)`; `Character Accuracy = 1 − CER`. Значение не обрезается снизу: лишние вставки могут дать отрицательную accuracy.
- `WER = Σword_edit_distance / Σreference_words`.
- `eligibility_coverage = eligible_zones / all_reference_zones`; `processing_coverage = processed_eligible_zones / eligible_zones`; `abstention_rate = abstained_or_low_quality_eligible / eligible_zones`.
- Порог Character Accuracy ≥0.95. CER, WER и обе coverage публикуются вместе; высокий процент на малой выбранной части не скрывает исключения.

## Поля, связка, локализация и нарушения

| Показатель         | Числитель / знаменатель                                                                                                       | Порог |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ----- |
| Fields Exact Match | Полностью совпавшие нормализованные поля / все ожидаемые поля; missing/abstained остаются в знаменателе                       | ≥0.90 |
| Linkage            | Группы с точным object_id, стадией, шифром и актуальной редакцией каждого источника / все группы, где предусмотрены источники | ≥0.95 |
| Localization       | Группы с полным комплектом: точные file_id/страница, для каждого фрагмента IoU≥0.50 / все группы с требуемыми evidence        | ≥0.95 |
| Precision          | TP/(TP+FP)                                                                                                                    | ≥0.90 |
| Recall             | TP/(TP+FN)                                                                                                                    | ≥0.80 |
| F1                 | 2TP/(2TP+FP+FN)                                                                                                               | ≥0.85 |
| FPR                | False violation predictions / заранее NEGATIVE_VERIFIED или случаи устаревшей редакции (объединение без дублей)               | ≤0.10 |

TP требует совпадения atomic parameter/location, типа расхождения и корректных полных evidence. Неверный тип/доказательство на положительном эталоне даёт FP за неверное предсказание и FN за пропущенный истинный finding. Неизвестное universe предсказание — FP. FN включает пропущенный положительный случай и abstention. TN — только явный корректный CLEAR на verified negative; abstention не объявляется TN. Для FPR зафиксированный universe negatives остаётся в знаменателе при abstention, а его доля раскрывается отдельно; высокая abstention не позволяет объявить систему принятой по одному FPR.

Missing evidence, not applicable и revision conflict не смешиваются с verified negatives: публикуются отдельные количества/исходы. Revision conflict с пометкой obsolete_revision_case дополнительно входит в знаменатель FPR. Неизвестность не становится автоматическим нарушением. Наряду с total micro-метриками нужны те же показатели по объекту, разделу и типу; отсутствующая обязательная категория имеет `NOT_EVALUABLE`, не PASS.

IoU = площадь пересечения / площадь объединения в системе координат видимой страницы после Rotate/CropBox/MediaBox. Исполняемый примитив сейчас принимает нормализованные прямоугольники `[left,top,right,bottom]` в [0,1]. Polygon нельзя молча заменить bounding box: для polygon GOLD перед фактической приёмкой нужен отдельно проверенный polygon-IoU либо согласованный прямоугольный эталон. Отсутствие bbox-GOLD в публичных page-level примерах не позволяет считать localization.

## CI95 и решение о приёмке

Для фактической оценки используем object-cluster percentile bootstrap: 2000 повторов, seed20260927, выборка с возвращением целых object_id с сохранением всех страниц/полей/групп объекта; в каждом повторе заново считаются суммы/доли, затем квантили2.5%/97.5%. Это закреплённый инженерный выбор метода CI, не якобы предписанная ТЗ формула. Одинаковый dataset/seed даёт одинаковый интервал. Для каждого показателя сохраняются число объектов, n, число валидных повторов и метод.

При менее2 независимых объектов либо <95% повторов с определённым знаменателем интервал `null` с причиной. Такой результат не подтверждает требование CI. Малое число объектов и дисбаланс обязательно отмечаются, даже если интервал вычислен. Внутри одного объекта можно показать точечную диагностику, но нельзя выдавать страницы этого же объекта за независимые стройки.

Пустой знаменатель всегда `null/NOT_EVALUABLE`, не 0 или1. Порог применяется к точечной оценке как в ТЗ, а CI публикуется отдельно: нельзя подменить его неназванным правилом «нижняя граница выше порога». Заключение требует всех обязательных порогов, категорий и надёжных исходных эталонов; сводный F1 не компенсирует провал OCR/FPR. H измеряет прототип и раскрывает ограничения по QA H9; это не промышленная F-приёмка.

## Ручные контрольные примеры

| Вход                                                         | Ручной результат                            | Автопроверка                |
| ------------------------------------------------------------ | ------------------------------------------- | --------------------------- |
| Reference `a b c`, prediction `a b x`, 300dpi                | 5символов, edit1: CER.2, accuracy.8; WER1/3 | test OCR control            |
| Eligible `abc`, ABSTAIN                                      | CER1, accuracy0; processing coverage0       | test abstention denominator |
| Три поля: `1.0`/`1`, `РД`/`рд` case-insensitive, `A`/missing | Exact Match1/3, coverage2/3                 | test fields                 |
| TP=FP=FN=TN=1                                                | P=.5, R=.5, F1=.5, FPR=.5                   | test confusion              |
| Положительный finding с неверной страницей                   | TP0, FP1, FN1; localization0                | test wrong proof            |
| Unit square и его левая половина                             | IoU=.50                                     | test IoU threshold          |
| Два объекта со значениями0 и1                                | Cluster bootstrap CI95=[0,1]                | test interval               |
| Пустой набор / один объект для CI                            | null, причина; не успех                     | tests empty/independence    |

Все fixtures названы synthetic; они проверяют арифметику и отрицательные случаи, не являются продуктовым acceptance evidence. Будущий отчёт ACC2/4 должен дополнительно фиксировать candidate_digest, dataset/matrix/model/method versions, input_manifest_hash, hardware, cohort breakdown, skipped/errors и ссылки на независимый запуск.
