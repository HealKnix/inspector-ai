Это техническое выделение validation внутри организаторского TRAIN_PUBLIC, а не изменение внешнего split. Все редакции/страницы/производные одного объекта наследуют его роль. Публичная доступность и прежнее исследование корпуса не дают гарантии, что validation никогда не видел разработчик: для объективного заключения необходим независимый hidden. Один train-объект и один validation-объект недостаточны для количественной приёмки и надёжного CI по объектам.

Машинный [development-split.json](development-split.json) фиксирует версии/хеш manifest. Для каждого входного файла в [permitted-manifest.json](contracts/permitted-manifest.json) сохранены file/object/split/stage/hash/page count без текста и меток. Хеши public оригиналов независимо подтверждены [проверкой](contracts/public-file-integrity.json); хеши hidden оригиналов здесь только заявлены публичным manifest и не объявлены независимо проверенными.

## Роли данных и процедура hidden test

Это роли хранения и использования данных, не новые роли/права приложения:

1. Разработчик/PAR/ML получает разрешённые train данные; validation используется для выбранного эксперимента, версии и пороги сохраняются. Изменение object split создаёт новую версию, но не отменяет факт предыдущего доступа к данным.
2. Куратор GOLD проверяет полноту карточки, экспертное решение/причину/дату, версии и SHA; выпускает dataset_version. Предразметка и SUSPICION до этого не обучающие метки.
3. Независимый хранитель до candidate фиксирует hidden input_manifest и SHA разметки, object_ids, пять категорий: confirmed positive, verified negative, missing evidence, not applicable, revision conflict. Категории и размеры можно передать без ответов. Отсутствующую категорию нельзя заменить синтетикой в официальном заключении.
4. Команда передаёт digest контейнеров/моделей/rules/matrix и runtime-конфигурацию. Оценщик запускает их на чистых документах без доступа к GOLD; входы приложения не содержат evidence images, annotations, public/hidden checks или решения экспертов.
5. Оценщик отдельно сопоставляет ответы с hidden GOLD и выпускает отчёт по объектам/разделам/типам: n, coverage, abstention, CI95, каждый порог, версии и ошибки. Повторный candidate получает новый digest/отчёт. Настройка по hidden-ответам запрещена.
6. Публичный выпуск содержит агрегаты и digest; закрытые исходные метки/документы не входят в Git, Docker image, logs, exports или train snapshot. Подписанное подтверждение состава/независимости хранителя — вход для ACC4, не условие запуска приложения.

Пока независимый хранитель не дал подтверждение состава/хешей и bbox/OCR эталоны, фактическая полнота hidden, CI и качество по §14 имеют состояние `NOT_RUN/INPUT_REQUIRED`. Процедура и допустимые данные уже определены; доступ к скрытым ответам у команды для этого не нужен.
