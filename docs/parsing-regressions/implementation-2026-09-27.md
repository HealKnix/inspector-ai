# Native-текст и выборочный OCR: реализация 27.09.2026

Работа относится к PAR 8.1–8.4 изменения `add-document-parsing`. Подготовлена также совместимость нового профиля для 8.7; выпуск нового Run и полный интеграционный сценарий 8.8 учитываются отдельно. Это продолжение действующего плана после аудита 26 сентября.

## Поведение

- Пригодный текстовый слой имеет приоритет на своём участке страницы. OCR получает непокрытые строки разрешённых текстовых и табличных областей. Graphic/unknown сохраняют запрет OCR.
- Каждый выбранный текст и его альтернативы имеют исходный текст, источник и координаты. Конфликтующие прочтения не конкатенируются. Конфликт native/native не разрешается случайным совпадением одного кандидата с OCR.
- Значения ячеек собираются из привязанных исходных фрагментов. Табличная модель задаёт структуру, но её текст без подтверждённого источника не становится самостоятельным доказательством.
- Строка, пересекающая колонки обозначения и названия, остаётся целой. `table_link` связывает её с существующей строкой таблицы; подтверждённая связь используется для поиска количества и единицы. Неоднозначные связи остаются явными.
- ID и EXT используют общий отбор блоков. Пригодный native-текст skipped-областей доступен с исходными локаторами; подавленные дубли и неоднозначные прочтения исключаются. Viewer может подсветить такой блок при переходе по локатору.

## Совместимость

Версии: `par-local-2`, `paddle-regions-v2`, `pp-structure-v3-guarded-v2`, `par-text-provenance-v1`. Основная схема артефакта остаётся `schema_version=1`, новый PDF содержит `text_provenance_schema_version=1`. Backend/OpenAPI/frontend принимают добавочные поля согласованно; legacy не получает выдуманного происхождения или пригодности native.

Версии, настройки, модели и исходники Python входят в fingerprint. Новый профиль использует отдельные артефакты и checkpoints. Проверка возврата к прежнему fingerprint подтверждает сохранность старого checkpoint, артефакта и оригинала; это тест кеша, а не испытание отката развёрнутого приложения с базой данных.

## Источники проверки

[Регрессионный набор](README.md) содержит пять дефектов единиц, строку Пеноплекса, лист изменений с 46 native-блоками и два фрагмента настоящих растровых страниц. [Манифест](../../backend/document-parser/tests/fixtures/native-ocr/manifest.json) фиксирует исходные hashes и геометрию. Полные PDF и модельные артефакты остаются в локальном игнорируемом каталоге.

Реальный прогон выполняется `backend/document-parser/experiments/native_ocr_probe.py` в существующем образе зависимостей `inspector-release-parser:foundations-20260927-r6`. Текущий код подключён read-only; сеть выключена; локальные модели подключены read-only. Короткие имена приватных копий обходят ограничение Docker Desktop на длинный компонент пути; SHA-256 каждой копии совпадает с оригиналом до запуска, оригиналы повторно проверяются после него. Выбранные страницы копируются в PDF без растеризации с явным соответствием номерам оригинала.

Запечатанный стенд `inspector-foundations-r8`, его манифест и исходный Docker-проект не меняются этим прогоном.

Воспроизведение из корня репозитория при наличии объявленных оригиналов, образа и локального model volume:

```text

```

Имя каталога должно быть новым. Launcher отказывается перезаписывать предыдущий прогон. Проверка unit/regression в том же образе, без загрузки моделей:

```text

```

## Граница результата

Эти регрессии не являются общей оценкой OCR. CER/WER требуют эталонной транскрипции всей измеряемой выборки; confidence и readable не выдаются за точность. Исходное DPI растровых страниц неизвестно. GPU не измерен. Validation и hidden-источники для данного ремонта не открывались. Действующие ограничения layout сохраняются: пропущенная unknown-область не получает OCR, даже если она содержит растровый текст.

Конфликтный текст остаётся в PAR с объяснением и исключается из автоматического извлечения. При отсутствии других фактов EXT возвращает `no_evidence`; конкретная PAR-причина конфликта пока не переносится в причину EXT. Это ограничение объяснимости, а не утверждение об отсутствии документа или нарушении.

После этого ремонта по плану остаются общий отчёт качества 8.5, GPU-профиль 8.6, выпуск с новым Run и проверкой истории 8.7, полный интеграционный прогон с viewer 8.8. Частичные проверки этих пунктов не закрывают их целиком.
