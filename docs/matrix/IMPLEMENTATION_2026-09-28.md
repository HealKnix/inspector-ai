# Реализация матрицы: срез 28.09.2026

Продолжены источники этапа 2 и составные условия этапа 4 согласованного плана. Реализована явная карта листов одного PDF с частичной заменой 1:1 и ограниченный AND/OR над одной величиной. **Новых предметных допусков по-прежнему 0/132.** Исторические 12 правил не переутверждены; успешные синтетические проверки ниже не являются приёмкой строк Матрицы.

## Что изменилось

| Часть                   | Результат и граница                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ID                      | Инспектор задаёт обозначение каждого листа отдельно от физической страницы, явные исключения и основание. Карта привязана к единственному PDF и SHA-256 оригинала; все страницы должны быть учтены                                                                                   |
| Частичная замена        | Отдельная `sheet_replacement`, несовместимая с полной заменой. Листы 1/4/8 переходят к новой редакции, 2/3/5/6/7 сохраняют прежние источники. У каждого листа остаются редакция, оригинал, PAR hash и физический локатор                                                             |
| Применимость источников | Все используемые редакции должны иметь отдельное подтверждение и покрывать период. Цикл, чужая область, неизвестное обозначение, неполная карта и конфликт блокируют сравнение. Найденный текст разрешения не принимает карту или approval                                           |
| EXT                     | Поиск anchors/regex/table/cascade выполняется после отбора действующих страниц. `selection_key` разделяет результаты контекстов; старое извлечение целого файла не подставляется в листовой выбор                                                                                    |
| COM и история           | Комплектность получает редакции унаследованных источников. Карта не подтверждает полноту всего объекта. Новый Run повторно использует PAR; прежние снимки, извлечения и протокол сохраняются. Перенос решения учитывает карту/основания, а не новый технический ID кэшированного PAR |
| COMP/CMP                | Версионированные AND/OR, три исхода, отдельная применимость, scalar-листья прежнего CMP, полная трасса всех ветвей. Лимиты: 64 узла, глубина 6, 2–8 детей. Разные величины, presence, геометрия и события этой реализацией не покрываются                                            |
| Серверный допуск        | Существующий runner вычисляет ветви сам; паспорт, версии, основания и ожидаемый исход каждого узла обязательны. Подмена ветви при прежнем общем результате и неподдержанный оператор блокируют approve                                                                               |
| Интерфейс               | Редактор карты и замены через прежний API; просмотр объединённого набора с переходом к исходнику; трасса AND/OR с причинами unknown. Подтверждение реквизитов не подтверждает approval                                                                                               |

В рабочем pipeline пока нет предметного подтверждения применимости составного параметра. Готовый выбор документов не заменяет его: составное правило возвращает `unknown` и не выполняет арифметику листьев. В синтетическом regression-runner применимость передаётся явно с отдельным основанием.

Версии: `sheet-document-identification-v4`, `sheet-document-grouping-v2`, `explicit-sheet-period-selection-v2`, `extraction-engine-v4`, `comparison-engine-v4`, `composite-scalar-v1`. Изменение версии исполнителя требует совместимой регрессии/партии для новых расчётов; исторический предметный допуск не придумывается.

Финальный candidate `revision-2026-09-28T13-18-46-101Z` после исправления навигации прошёл проверку здоровья всех сервисов. [Повторная read-only API-проверка от 28.09](identification-api-2026-09-28.json) — **PASS: 5 кандидатов реквизитов, 3 снимка**, исполнитель `sheet-document-identification-v4`. Проверка выполнена на ранее разрешённом диагностическом объекте через реальные worker/PostgreSQL/API; редакция и карта листов при этом не утверждались (`accepted_revision=false`, `selected_sheets=false`). Сохранены только реквизиты, идентификаторы, хеши и локаторы доказательств; учётных данных в отчёте нет. Прежние снимки сборок и отчёты сохранены.

После миграции совпали количества и MD5 канонических строк: 6 files, 2 runs, 120 extractions, 192 evidence groups; в candidate нет исторических protocols/findings. При сравнении извлечений исключён только новый nullable `selection_key`. Исторический протокол проверен отдельно в интеграционной БД. Отчёт — `post-sheet-20260928-integrity.json`.

При запуске Docker нужно явно указывать `-p inspector-matrix-candidate`. Ошибочный запуск без `-p` создал отдельные пустые контейнеры; они и их сети убраны, тома сохранены.
