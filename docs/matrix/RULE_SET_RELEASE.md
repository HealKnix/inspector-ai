# Закреплённый выпуск правил

Реализованы `RuleSetRelease`, ссылка `Run.ruleSetReleaseId` и единый выбор выпуска. Миграция `20260927020000_rule_set_releases` дополняет схему. Существующие Run не изменяются; их прежний предметный допуск неизвестен. БД запрещает UPDATE/DELETE выпуска и изменение Run.

Выпуск содержит точный каталог, планы, comparison/applicability, версии исполнителей, ссылки и hashes паспортов и успешных отчётов. SHA-256 канонического manifest защищает содержимое. Частичный выпуск перечисляет пропущенные коды. Полный требует ровно P001–P132, по одной версии, с совместимыми паспортами/отчётами и реализованными обязательными ветвями.

Администратор использует существующие права и аудит:

| Операция                                                   | Результат                                                           |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| GET `/api/v1/admin/matrix/releases`                        | Выпуски и текущий выбор                                             |
| POST на тот же адрес `{mode, rule_ids}`                    | Неизменяемый состав; повтор возвращает тот же manifest              |
| GET `releases/:id`                                         | Точное содержимое выпуска                                           |
| POST `releases/:id/publish` с `expected_active_release_id` | Атомарный выбор для новых Run; несовпадение ожидаемого выбора — 409 |

Сборка не публикует. Публикация повторно проверяет каталог, исполнителей и основания. Совместимый прежний выпуск выбирается тем же явным действием; deprecated версия с сохранённым допуском может использоваться при откате. Новое утверждение отдельного правила не изменяет уже закреплённый Run.

При отсутствии выбранного проверенного выпуска новый Run получает неизменяемый `legacy_capture` действующих исторических версий. Это сохранение совместимости, **не новый допуск**: admitted_parameters=0. Такой снимок запрещено публиковать как проверенную партию. У старых Run без ссылки исторический состав не восстанавливается по догадке.

План и сравнение обработчик читает из снимка Run. Manifest input фиксирует hash выпуска. В протоколе перенос решения зависит от конкретного правила, оснований, исполнителей и исходных доказательств; изменение другого параметра само по себе не меняет этот отпечаток. Совпадение значения при смене редакции, локатора или основания недостаточно для переноса.

Группа и finding сохраняют `verdict.rule_basis`: точный паспорт по ID/hash из закреплённого выпуска. Перед сохранением проверяются hash содержимого и принадлежность RuleVersion. Инспектор видит исходный триггер, область, применимость, редакцию и пункт основания из этого снимка. Текущий административный паспорт при историческом чтении не подставляется. Для legacy-группы отсутствующее основание не выдумывается.

Интерфейс администратора показывает паспорт, серверную допустимость утверждения, регрессии и состав партии. Обзор инспектора получает результаты из полного API, отдельно от очереди вопросов, и показывает число исполнимых и допущенных правил. Качество на независимом корпусе не вычисляется из этих счётчиков.

Интеграционные проверки выполняются на отдельной случайной БД PostgreSQL: отказ без регрессии, неизменяемость, конкурентная публикация, закрепление Run, откат, откат транзакции при ошибке аудита. Отдельные проверки отвергают 131 строку, повтор, повреждённый hash, неподдерживаемый оператор и несовместимого worker.

Перенос нового проверенного выпуска в офлайн-пакет ещё не реализован: нужны переносимые разрешённые fixtures, связанные справочники и проверка полного импорта. Исторический offline-catalog сохраняет прежнее ограничение и не выдаётся за MAT-экспорт. Промышленная приёмка 132/132 остаётся открытой.
