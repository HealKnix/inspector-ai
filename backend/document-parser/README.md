# Локальный парсер документов

Python-сервис реализует внутренний контракт PAR: читает UUID оригинала,
проверяет SHA-256, возвращает текст, страницы, координаты, качество и покрытие.
Все изображения пишутся под новыми UUID. Данные предметной БД меняет backend.

## Запуск

Образ собирается из корня репозитория:

```sh
docker build -f backend/document-parser/Dockerfile -t inspector-document-parser .
```

Перед первым запуском отдельно выполните `python download_models.py` в образе с
записываемым томом `/models` и доступом в сеть. **Тома документов в этом шаге
не подключаются.** Скрипт скачивает девять моделей PP-StructureV3 (OCR, ориентация,
разметка страницы и таблицы), проверяет 27 файлов по `model-lock.json`.
Уже сохранённые файлы используются после проверки. Затем `/models` подключается только
для чтения к сервису `python server.py` без внешнего сетевого доступа.

Compose корня проекта предоставляет эти операции и долговечные тома. Runtime
работает как UID/GID 1000; каталог `STORAGE_ROOT/originals` должен читаться,
`STORAGE_ROOT/derived` — допускать запись. Оригиналы монтируются только для чтения.
Внутри OCR-процесса сетевые соединения дополнительно запрещены; XML entities,
DTD, внешние DOCX relationships, макросы и включения не выполняются.

Обязателен `PARSER_TOKEN` длиной не менее 32 символов. Все эндпоинты, включая
`GET /health`, требуют `Authorization: Bearer …`. `/health` становится успешным
только после проверки файлов и загрузки моделей в переиспользуемый процесс.
`POST /parse` возвращает полный артефакт; `GET /progress/:request_id` показывает
фактическое число законченных страниц. `POST /cancel/:request_id` завершает
активный CPU-процесс и возвращает `{ "cancelled": true }`. Повторы и долговечный
статус принадлежат backend. Ошибки HTTP имеют безопасный код в нижнем регистре.

| Переменная                    | По умолчанию                                      |
| ----------------------------- | ------------------------------------------------- |
| `STORAGE_ROOT`                | `/data`                                           |
| `PARSER_MODEL_ROOT`           | `/models`                                         |
| `PARSER_FONT_PATH`            | `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` |
| `PARSER_PORT`                 | `8090`                                            |
| `PARSER_FILE_TIMEOUT_SECONDS` | `600`                                             |
| `PARSER_CPU_THREADS`          | `2`                                               |
| `PARSER_MAX_FILE_BYTES`       | `104857600`                                       |
| `PARSER_MAX_XML_BYTES`        | `52428800` (также суммарный распакованный DOCX)   |
| `PARSER_MAX_PAGES`            | `500`                                             |
| `PARSER_MAX_RENDER_PIXELS`    | `20000000` на страницу                            |
| `PARSER_RENDER_DPI`           | `200`                                             |
| `PARSER_MAX_BLOCKS`           | `100000` на документ                              |
| `PARSER_MAX_OUTPUT_BYTES`     | `52428800`                                        |

Один процесс выполняет один файл. Параллельный запрос получает `parser_busy`.
Таймаут и отмена вызывают terminate, затем kill при необходимости; CPU-задача
действительно прекращается. После этого создаётся новый процесс с моделями.
Дополнительные лимиты памяти/CPU и сетевую изоляцию задаёт Compose. Завершённые
страницы PDF сохраняются как checkpoints по хешу исходника и полной версии
обработчика; повтор после таймаута может продолжить со следующей страницы.
Checkpoints — локальное ускорение; публикация артефакта остаётся в backend.

Перед возобновлением проверяются все сохранённые страницы: metadata SHA,
номер страницы и SHA изображения. Прогресс считает подтверждённые страницы,
включая находящиеся после пропуска; повреждённые страницы обрабатываются заново.
Во время проверки backend сохраняет прежний счётчик с соответствующей подписью.
Прогресс Python содержит request_id, pipeline_fingerprint, stage,
checkpoint_validated, checkpoint_pages и current_page; backend принимает его
только для актуального исполнения. Повторный опрос неизменного снимка не
обновляет время фактического прогресса.

Ожидание `models_not_ready` ограничено backend-параметром
`PARSER_MODEL_READY_WAIT_SECONDS=300` (30–1800 секунд). Срок сохраняется в БД
и не продлевается рестартом или повторной доставкой. Ожидание не расходует
три реальные попытки; исчерпание срока даёт `models_not_ready_timeout` и
обычный ручной повтор. Здоровый `/health` не равен допуску `/parse`.

## Извлечение и ограничения

PDF использует региональный профиль `paddle-regions-v1`. Первый layout-only
эксперимент выявил пропуски таблиц/подписей и ошибку «схема как таблица»;
после просмотра отчёта владелец разрешил внедрение с последующим улучшением
качества. [Отчёт](../../docs/adaptive-layout-experiment.md) остаётся фактическим
описанием ограничений. Разметка не гарантирует правильного понимания чертежа.

- PDF: `PP-DocLayout_plus-L` размечает исходное изображение без маскирования;
  затем привязывается и сохраняется весь текстовый слой.
  Категории: text/table/graphic/unknown.
  Неподдержанный класс, неуверенность, конфликт границ и неразмеченное
  содержимое сохраняются с причиной; graphic/unknown не получают OCR.
  Штамп не определяется по положению на листе: обрабатывается его найденный
  класс text/table. Уверенно ошибочная table всё ещё может содержать план.
- Для text/table детектор строк проверяет покрытие пригодными native-блоками:
  корректные Unicode, координаты и направление, не менее 90% тёмных пикселей
  внутри полигона строки, допуск 2 пикселя. Белые поля детектора и длинные
  линии таблиц не учитываются; пустая маска не подтверждает покрытие.
  Фиксированные белые поля 16 px при детекции помогают читать тесные области;
  координаты возвращаются внутрь исходной области, наружный текст не добавляется.
  Эти параметры маршрутизации входят в fingerprint и не
  являются метрикой точности. Распознаватель получает только непокрытые строки;
  линии и векторы сами по себе больше не запускают OCR всей страницы.
  Области рендерятся из исходного PDF с фиксированным DPI и лимитом пикселей;
  автоматической цепочки увеличений разрешения нет. Координаты возвращаются
  в исходное отображение; произвольный наклон и перспектива не исправляются.
- OCR: рабочий pipeline `PP-StructureV3`, `PP-OCRv5_mobile_det` (1536 px) +
  `eslav_PP-OCRv5_mobile_rec`, CPU, oneDNN выключен
  из-за воспроизведённой ошибки Windows-пробы. Рукопись, схемы, печати и мелкие
  символы могут читаться плохо. Любая распознанная область получает
  `OCR_UNVERIFIED`; оценки модели не являются измеренной точностью. Неудача
  чтения даёт явную причину; плановый пропуск графики сам по себе не является
  плохим качеством или отсутствием содержимого. Coverage считает страницы
  с извлечённым текстом, а не полноту будущей проверки Матрицы.
  Пустые текстовые блоки, состоящие только из пробелов/переносов, не публикуются;
  пустые ячейки настоящих таблиц сохраняются. Старый артефакт не переписывается:
  viewer скрывает его пустые OCR-текстовые фрагменты при отображении.
- Таблицы растровых страниц: компоненты PP-StructureV3 получают отдельную
  область и уже выбранные native/OCR-строки; внутреннее повторное OCR и
  повторное определение разметки выключены. Адаптер сохраняет текст, пустые ячейки,
  строки/столбцы/объединения и координаты на исходном PNG. HTML преобразуется в
  данные, скрипты/разметка модели не выполняются. Непригодные сетки
  отклоняются с `TABLE_STRUCTURE_REJECTED`; общий OCR и
  дополнительные распознанные строки остаются доступны. Результат требует
  проверки (`TABLE_STRUCTURE_UNVERIFIED`), сложные схемы надёжно не поддерживаются.
  Проверяются пересечения индексов, согласованность осей и чрезмерные пересечения
  bbox ячеек. Поддерживаются до 2048 ячеек, 1000 позиций на ось и 10000 позиций
  сетки на таблицу; превышение даёт текст без принятой структуры. Площадь таблицы
  сама по себе не служит основанием для отказа.
  У отличающегося текста без точного локатора сохраняется область всей таблицы
  и явный structural_path; точность до отдельной строки не выдумывается.
  Native-таблицы разбираются PyMuPDF с ограничением областью и обходом
  CropBox+Rotate. Неудача восстановления ячеек сохраняет native-текст и
  неподтверждённую структуру; пригодный текст не отправляется в OCR повторно.
  [Предварительная проверка](../../docs/pp-structure-v3-experiment.md) показывает
  известные ошибки числовых знаков и ложных таблиц на чертежах.
- DOCX: извлекаются абзацы, таблицы с gridSpan/vMerge, текстовые поля, колонтитулы,
  сноски, примечания. Воспроизводимое структурное представление **не повторяет
  вёрстку Word**. Доступные через внутренние image relationships растры
  PNG/JPEG/BMP/TIFF/WebP получают собственные страницы и локальный OCR; transform
  сохраняет part и relationship, а фрагменты — путь к медиа. Только первый кадр
  многостраничного изображения обрабатывается с явной причиной ограничения.
  Неподдерживаемые объекты, векторные EMF/WMF, внешние и неиспользованные медиа
  отмечаются причинами низкого качества; удалённые ресурсы не загружаются.
  Удалённый, вставленный и перемещённый текст правок выводится отдельными
  подписанными фрагментами; инструкции полей отделены от значений. Правки не
  принимаются автоматически, исходные варианты не склеиваются в один шифр;
  `DOCX_TRACKED_CHANGES` и `DOCX_FIELD_INSTRUCTIONS` требуют проверки.
- XML: атрибуты, namespace-пути, текст и смешанное содержимое в порядке документа
  отображаются с локаторами. Схемы, ссылки и внешние ресурсы не загружаются.
- DOCX/XML: DejaVu Sans, фиксированные размеры и алгоритм разбиения дают
  `structural_path → page/bbox`. `DOCX_SEMANTIC_RENDER`/`XML_SEMANTIC_RENDER` —
  информация о представлении; сами по себе не снижают качество. Исходные табы,
  пробелы и переносы сохраняются в raw_text, нормализация использует NFC и
  повторные горизонтальные пробелы, не исправляя буквы или шифры.

`width`/`height` — размеры PNG в пикселях; bbox относится к видимой странице
после CropBox/Rotate. PDF transform содержит MediaBox/CropBox, поворот,
прямую/обратную матрицу из PDF-координат в видимые координаты в пунктах и
отдельные матрицы native-координат MuPDF. Единицы матриц обозначены
`matrix_coordinate_space: visible-page-points`; дополнительно сохранены
`pdf_to_normalized` и `normalized_to_pdf`. Чтобы получить нормализованную точку,
после матрицы разделите x/y на visible_width_points/visible_height_points.
Сохранение PNG выполняет fsync файла и каталога перед возвратом результата.

Fingerprint включает код, версии библиотек, SHA моделей/шрифта и все значимые
параметры. Изменение любого из них исключает повторное использование старого
артефакта. Изменения моделей требуют явного обновления lock и оценки качества.

Новый PDF-артефакт добавляет `region_schema_version: 1`, `pages[].regions`
и обязательные `region_id`/`include_in_main` у каждого фрагмента. Native-надписи
graphic/unknown сохраняются в полном raw/normalized тексте, но исключены из
основного списка. Альтернативные чтения ячеек также сохранены; полный текст
может содержать повторы. Изображение области — неизменённый PNG страницы и bbox.
API проверяет полные связи, допустимые методы и отсутствие OCR в пропущенных
областях. Старые результаты читаются без выдуманной разметки; DOCX/XML сохраняют
прежний структурный маршрут. Полный `PPStructureV3.predict()` остаётся только
для вложенных растров DOCX, PDF вызывает отдельные компоненты адаптера.

## Проверки

```sh
python -m unittest discover -s backend/document-parser/tests -v
```

Синтетические проверки покрывают CropBox и четыре поворота с попаданием
глифов в bbox, обратные матрицы, смешанный XML, атрибуты, DTD, DOCX-структуру,
raw/normalized текст, ячейки отсканированной таблицы с объединением,
пустую страницу, hash/traversal, image-only DOCX с внутренней/внешней ссылками,
ограничение числа OCR-проходов, целостность checkpoints, воспроизводимость PNG
и принудительное завершение CPU-процесса. PP-StructureV3 дополнительно проверяется
на сохранение общего OCR и альтернативного текста таблиц, четыре поворота,
crop, пустые/объединённые ячейки, некорректные сетки, полноценную таблицу на всю
страницу и изменение fingerprint. На 2026-09-18 выполнено 28 проверок.

Короткий реальный OCR-прогон можно воспроизвести генератором:

```sh
python backend/document-parser/tests/generate_synthetic.py --output /private/synthetic
python backend/document-parser/benchmark.py --source-root /private/synthetic \
  --manifest /private/synthetic/manifest.json --output /private/synthetic-result \
  --models /models
```

Исторический прогон до подключения PP-StructureV3, 2026-09-18 на Windows, Python 3.12.10,
CPU (2 потока, параллельно выполнялась Docker-сборка): загрузка трёх моделей —
41,715 с. Для каждого примера размечены **37 символов / 6 слов**:

| Синтетический пример                               | Секунды |  CER | WER | Качество    |
| -------------------------------------------------- | ------: | ---: | --: | ----------- |
| DOCX с изображением                                |   3,503 | 0/37 | 0/6 | LOW_QUALITY |
| PDF с текстовым слоем и CropBox                    |   0,815 | 1/37 | 1/6 | OK          |
| PDF из native-страницы и скана с CropBox/Rotate=90 |   6,132 | 2/37 | 1/6 | LOW_QUALITY |

Оставшиеся расхождения — похожие латинские/кириллические буквы; нормализация не
подменяет их по предположению. `OK` означает чтение текстового слоя, а не
независимо измеренную безошибочность документа. Малые контрольные примеры
проверяют работающую цепочку, а не точность на корпусе. Все три полных артефакта
прошли runtime-схемы backend и браузера. Отдельная проверка
классификатора на трёх разрешённых страницах в четырёх поворотах дала ожидаемый
поворот в 12/12 случаях, 0,14–0,20 с после прогрева. Эти наблюдения не заменяют
измерения Docker/Linux, разметку трудных сканов и независимую приёмку.

Для разрешённого validation-корпуса используйте `benchmark.py`. Манифест и
выходной каталог должны быть **вне репозитория**:

```json
[
  { "id": "act-native", "path": "relative/file.pdf" },
  {
    "id": "annotated-scan",
    "path": "relative/scan.pdf",
    "truth": {
      "page_number": 1,
      "text": "Вручную проверенный текст всей страницы"
    }
  }
]
```

```sh
python backend/document-parser/benchmark.py \
  --source-root /approved/corpus --manifest /private/manifest.json \
  --output /private/par-validation --models /models
```

Сохраняются безопасный отчёт с версиями/таймингами/покрытием и отдельные полные
артефакты в указанном закрытом каталоге. CER/WER считаются только для явно
переданной ручной разметки; без неё `accuracy: null`. Это локальная проверка,
а не скрытая независимая приёмка C24 и не заявление о достижении процента OCR.

Первичные источники API:
[PyMuPDF Page/rotation](https://pymupdf.readthedocs.io/en/latest/page.html),
[PaddleOCR local models](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/OCR.en.md).
